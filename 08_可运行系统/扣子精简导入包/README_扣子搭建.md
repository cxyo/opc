# 扣子侧精简导入包 · 3 个 Bot

> **为什么不建 21 个？**
> 本地系统已经把 21 个岗位跑起来了（见 `08_可运行系统/`）。扣子只负责**需要云端定时、需要在你不在电脑时自动跑**的活。
>
> 建 21 个 Bot 的成本：21 × (建 Bot + 配知识库 + 调参数 + 测试) ≈ 15-20 小时。
> 建 3 个的成本：1.5 小时。**同样的事，先做省 90% 时间的版本。**

---

## 一、只建这 3 个

| Bot | 岗位 | 为什么留它 | 扣子里怎么触发 |
|-----|------|-----------|--------------|
| **Bot 1** | A10 质检官 | 安全底座，误判代价最大 | 手动 / 被工作流调用 |
| **Bot 2** | A16 GEO优化官 | 唯一复利岗，**必须**定时跑 | 每周一 09:00 定时 |
| **Bot 3** | A03 情报官 | 采集类任务，本地跑不如云端挂着 | 每天 08:30 + 21:00 定时 |

**其余 18 个岗位全部在本地跑。** 需要哪个的时候用 `python run.py ask A07 "任务"` 调起来，效果一样。

---

## 二、建 Bot 的标准动作（每个 30 分钟）

### 第 1 步：建 Bot（2 分钟）

1. 打开 coze.cn → 工作室 → 创建 Bot
2. 名称：`质检官` / `GEO优化官` / `情报官`
3. 描述：见下面第二节

### 第 2 步：粘贴人设（3 分钟）

打开 `01_Bot提示词/A10_质检官.md`，找到「## 一、人设与回复逻辑」下面那个代码块，**整块复制**，粘到 Bot 的「人设与回复逻辑」字段。

> ⚠️ 代码块里是完整提示词，不要删减。约束条目是质检能力的来源，删了就退化成普通聊天机器人。

### 第 3 步：填开场白和建议问题（1 分钟）

同一个文件里：
- 「## 二、开场白」下的内容 → 粘到 Bot 的「开场白」
- 「## 三、建议问题」下的 3-5 条 → 粘到 Bot 的「建议问题」

### 第 4 步：建知识库并挂载（5 分钟）

| Bot | 知识库 | 怎么建 |
|-----|--------|--------|
| 质检官 | `KB_禁区` | 建 1 个知识库，把 `03_知识库/wiki/10_禁区/` 下 3 个 md 传进去 |
| GEO优化官 | `KB_内容素材` | 传 `02_知识库种子/` 下全部文件 |
| 情报官 | `KB_内容素材` | 同上 |

**禁区库必须手动分段**（重点）：

1. 打开知识库 → 文档 → 编辑分段
2. **把每一条红线单独做成一段**（不能整篇自动分段）
3. 每段开头手动加上平台前缀：`【公众号】`、`【小红书】`、`【抖音】`、`【闲鱼】`
4. 段内必须同时包含：禁止行为 + 判定关键词 + 严重级别

**为什么不能自动分段**：自动分段会把一条红线切成"条款""判定关键词""严重级别"三个片段。质检官检索时只命中"严重级别"那一片，判定就失效了。

### 第 5 步：设模型（1 分钟）

| Bot | 模型 | 温度 | 说明 |
|-----|------|------|------|
| 质检官 | **deepseek-reasoner** | 0.3 | 判定要准，宁慢不误 |
| GEO优化官 | deepseek-chat | 0.7 | 生成类，需要发散 |
| 情报官 | deepseek-chat | 0.4 | 采集类，要稳不要乱编 |

**扣子原生支持 DeepSeek**，不需要自己填 API Key、不需要接第三方。

### 第 6 步：测试（5 分钟）

打开 `02_扣子搭建手册/04_调试验收.md`，找到对应岗位的「陷阱测试」，逐条测。

**测不过不要往下走。** 质检官测不过，说明你的知识库分段有问题，回去检查第 4 步。

## 四、扣子 vs 本地：怎么分工

| 场景 | 用哪个 | 原因 |
|------|--------|------|
| 每天写文章 | **本地** | 你在电脑前，本地更快、产出直接落盘 |
| 写完要质检 | **本地** | 本地版本带禁区预检（自动命中判定关键词） |
| 定时采集情报 | **扣子** | 云端挂着，你不在电脑也跑 |
| 定时跑 GEO | **扣子** | 同上 |
| 临时叫某个员工干活 | **本地** | `run.py ask A07 "..."` |
| 一个人用手机查情报 | **扣子** | 扣子有 App |

**结论**：扣子是"云端值班员"，本地是"工作台"。不是二选一。

## 五、验收标准

建完这 3 个 Bot，逐条确认：

```
□ 质检官能判出违规稿（用"转发三个群领取"测）
□ 质检官能识别 AI 味（用一段典型的 AI 排比句测）
□ GEO 官能生成目标提问词库
□ 情报官能在定时任务里跑出结果
□ 三个 Bot 的人设代码块都是整段粘贴的，没删减
```

## 六、常见问题

**Q：本地和扣子的提示词会不会打架？**
不会。本地读的是 `07_AI员工/01_Bot提示词/` 同一批文件，扣子粘的是同样内容。改一处两边都生效（扣子要手动同步）。

**Q：我想加更多 Bot？**
先确认本地跑不顺手。只有**需要定时跑**的岗位才值得放扣子。

**Q：扣子额度够吗？**
质检官用 reasoner，一个 3000 字稿件大概 3000-5000 token。判定类建议一天不超过 5 篇。

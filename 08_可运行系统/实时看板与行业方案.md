## 一、实时看板（给客户看的「AI 在干什么」）

### 打开方式

控制台 → 顶部第二个页签「⚡ 实时看板」
或直接访问 `http://127.0.0.1:8899/#p9`

### 页面有什么

| 区域 | 内容 | 演示时怎么说 |
|---|---|---|
| **矩阵雨背景** | 绿色字符雨（Canvas，纯前端，不耗 CPU） | "这不是特效，是真的在跑" |
| **顶部状态条** | 绿点=待命 / 橙点=执行中；事件数、成功数、自动重试数、失败数、本次花费 | "右上角能看这次花了多少钱" |
| **当前任务流程** | 10 步链式图，实时变色 | "AI 走到第几步，一眼就知道" |
| **实时事件流** | 每次调用的时间戳、岗位、字数、耗时、费用 | "它具体做了什么，全都有记录" |
| **行业方案** | 一键切换整套 AI 员工的行业 | "换个行业，它就变成那行的员工" |
| **现场演示** | 三个按钮：跑成稿 / 只出图 / 生成交付包 | "点一下，全程可见" |

### 步骤链的颜色含义

| 颜色 | 状态 | 含义 |
|---|---|---|
| 🟢 绿 | 完成 | 这步成功了 |
| 🟠 橙 | 执行中 | 正在跑 |
| 🔴 红 | 失败 | 这步挂了，**不会带着错误往下跑** |
| 🟣 紫 | 自动重试中 | 失败了，系统正在自己修 |

### 失败了怎么办（用户最关心的问题）

看板会明确区分两种情况：

**① 自动修复中（紫色）**
```
↻ 自动修复中
第 1 次调用失败，系统正在自动重试（间隔 3 秒，最多重试 2 次）。
原因：TimeoutError
重试成功 → 继续下一步；重试仍失败 → 该步骤标记失败并中止流程。
```

**② 步骤失败，需人工介入（红色）**
```
✘ 步骤失败，需人工介入
错误：KeyError: 'xxx'
系统不会自动跳过这一步。已产出的成果保留在产出目录里，
修掉原因后可以只重跑失败的那一步，不用整套重来。
```

### 技术实现

| 部件 | 文件 | 说明 |
|---|---|---|
| 事件总线 | `staff/live.py` | 线程安全广播中心，`BUS` 全局单例 |
| SSE 端点 | `/api/live/stream` | `text/event-stream`，每 15 秒心跳防断连 |
| 历史查询 | `/api/live/recent` | 最近 120 条事件 + worker 心跳 |
| 埋点位置 | `pipeline.run_role` / `workflow.emit` / `console_server._worker` | 三个入口覆盖所有执行路径 |
| 前端 | `console_template.html` 的 `initLive` / `handleEvent` / `renderChain` | Canvas 矩阵雨 + SSE 订阅 |

**为什么要用 SSE 不用 WebSocket**：只需要服务器→浏览器单向推送。
SSE 用浏览器原生 `EventSource`，不需要额外库、不需要握手、断线自动重连。

**服务器必须多线程**：单线程 `HTTPServer` 会让 SSE 长连接占住唯一的服务线程，
页面上其它接口全部超时。已改成 `ThreadedHTTPServer`，
主循环也从 `handle_request()` 改成 `serve_forever()`。

### 埋点静默失效的坑（踩过，记录下来）

埋点代码全部包在 `try/except` 里（不能让埋点把主流程搞挂），
代价是**埋点坏了没人知道**。踩过的坑：

1. `pipeline.py` 少 `import time` → 埋点抛 `NameError` 被吞掉，事件永远不产生
2. `emit_order()` 内部写死 `data={...}`，调用方又传 `data=` →
   `TypeError: got multiple values for keyword argument 'data'`
3. `console_server.py` 的 `serve()` 和 `ThreadedHTTPServer` 类被误删
4. 前端 `const LV={roleStage:LV_ROLE_STAGE}` 但 `LV_ROLE_STAGE` 在后面声明 →
   **TDZ（暂时性死区）**，整个 `<script>` 块静默不执行，页面看起来"就是没数据"

**已加两道防线**：
- `live.self_check()` —— 启动时自检，失败会打印警告
- `live.safe()` / `live.note_error()` —— 统一的埋点入口，失败留痕不静默
- `工具脚本/检查前端脚本.py` —— 括号配平 + TDZ + Node 语法检查

## 二、行业方案（通用性）

### 行业包是什么

一个行业包 = 一套岗位 + 一批知识库 + 一套话术 + 一组交付物 + 一个视觉主题。

切换行业 = 换掉这些，等于把「AI 员工」派到另一个车间。

### 内置 5 个

| key | 名称 | 岗位数 | 交付物 |
|---|---|---|---|
| `general` | 🧠 通用办公提效 | 8 | 方案初稿、汇报材料、会议纪要、通知公告 |
| `robotics` | 🤖 工业机器人 | 8 | 设备档案、操作手册、排障手册、培训材料 |
| `helmet` | 🪖 头盔厂交付 | 4 | 上岗手册、操作卡、故障速查表、安全红线 |
| `ecommerce` | 🛒 电商运营 | 7 | 详情页文案、主图文案、评价分析、活动方案 |
| `marketing` | 📣 市场营销 | 7 | 活动方案、投放文案、私域话术、品牌手册 |

### 磁盘结构

```
一人AI公司/03_知识库/行业包/
├── robotics/
│   ├── pack.json          ← 岗位、知识库清单、交付物、话术风格
│   ├── 知识库/            ← 这个行业的全部资料（AI 的知识来源）
│   │   ├── 设备档案.md
│   │   ├── 客户操作手册.md
│   │   ├── 调试与排障手册.md
│   │   ├── 新员工上岗手册.md
│   │   └── ...
│   └── 过程文档/          ← 中间稿，不进知识库（避免检索重复）
└── helmet/
    ├── pack.json
    ├── 知识库/
    │   ├── 零基础员工问答库.md   ← 手写的大白话问答
    │   └── ...
    └── 过程文档/
```

### 切换后自动生效的

| 变化 | 生效点 |
|---|---|
| 岗位可见性 | 派活台下拉只显示该行业岗位（`console.py` 的 `render_console`） |
| 知识库范围 | 交付包与检索只取行业包 `知识库/` + 命中关键词的通用资料 |
| 人设档案 | `positioning.industry` 自动填行业名 |
| 交付物清单 | 交付包 README 按行业写 |

### 给新客户搭一套的标准流程

```bash
# 1. 从最接近的行业复制一份
cp -r "03_知识库/行业包/robotics" "03_知识库/行业包/头盔厂"

# 2. 改 pack.json（岗位、知识库清单、交付物、话术风格）

# 3. 换掉 知识库/ 里的资料（客户的设备档案、操作手册、故障案例）

# 4. 控制台 → 实时看板 → 行业方案 → 切到「头盔厂」

# 5. 点「生成客户交付包」→ 直接发给客户
```

辅助脚本：`工具脚本/建机器人行业包.py`（把尔必地资料转成行业包）

## 三、客户交付包

### 生成的 7 个文件

| 文件 | 给谁 | 干什么 |
|---|---|---|
| `01_上岗速通.html` | 新员工第一天 | 3 分钟看懂 + 最常问的问题 + 安全红线 |
| `02_操作卡.html` | 操作员 | 一个流程一张卡，打印贴工位 |
| `03_故障速查.html` | 操作员 | 输入现象直接查解决办法（带搜索框） |
| `04_设备档案.html` | 维护人员 | 参数、点位表、报警码 |
| `05_知识库.html` | 技术对接人 | 结构化知识库预览 |
| `知识库.json` | 系统对接 | 可直接导入别的知识库系统 |
| `README.md` | 客户方 | 说明每个文件给谁看 |

外加一个 `交付包_<行业>.zip`，直接发客户。

### 关键设计：区分「操作流程」和「技术参考」

知识库里混着两类内容：

- **操作流程**（开机、关机、换砂纸）—— 操作员照着做
- **技术参考**（IO信号表、点位表里的代码块）—— 工程师看的

判据：**来源文档名含「操作手册 / 上岗手册 / SOP / 流程」才算操作流程**。
技术流程另辟一节「📎 技术参考流程」，不混进操作卡。

### 知识库质量控制

| 机制 | 作用 |
|---|---|
| FAQ 去重 | 同一问题在原手册和抽取版里各出现一次 → 保留答案更长的 |
| 流程去重 | 高度相似的流程合并（短流程被长流程包含则跳过） |
| 行业关键词过滤 | 通用 raw 目录里 82 篇新媒体资料 → 机器人行业只留 7 篇精准的 |
| 空模板排除 | `create_pack` 生成的骨架（只有"第1步"没内容）不产出卡片 |
| 安全声明排除 | 「⚠️ 严禁 / 警告」这类块不是操作步骤 |

## 四、常见问题

**Q：切换行业会不会把原来的东西弄坏？**
不会。行业包只做「筛选 + 换知识库 + 换话术」，不改动原有的 23 个 AI 员工，
随时能切回来。

**Q：知识库里的资料没更新，AI 回答的还是旧的？**
知识库是每次调用时实时检索的（`pipe.kb.context`），不是缓存。
改了 `知识库/` 里的文件立刻生效，不用重启。

**Q：交付包里的内容是不是 AI 编的？**
不是。交付包全部由 `delivery.py` 从知识库文件里**解析**出来，
不调用任何模型。FAQ 是从原文的 `### Q1：xxx` 小节抽的，
流程是从原文的 ` ```text ` 代码块抽的，每条都能追溯到源文档。

**Q：客户不会用 AI 怎么办？**
交付包的设计前提就是「客户不需要懂 AI」。
他们只需要双击 HTML 文件，打印操作卡贴墙上，问维护人员。

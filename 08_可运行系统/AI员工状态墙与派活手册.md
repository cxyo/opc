# AI 员工状态墙 & 派活手册

> 这份文档回答两个问题：
> 1. **我的 AI 员工做好了吗？** —— 做好了，22 个岗位全部可调用、可计费、可查状态。
> 2. **我怎么给它们下达指令？** —— 三种方式，从简单到完整。

---

## 一、先看状态：谁在干活、有没有偷懒

### 网页版（推荐，最直观）

```bash
cd 一人AI公司/08_可运行系统
python run.py console
```

浏览器会自动打开 `http://127.0.0.1:8899/`，三个页面：

| 页面 | 看什么 |
|---|---|
| **状态墙** | 22 个员工的状态灯、token 消耗、产出字数、偷懒指数。点卡片直接跳去派活 |
| **派活台** | 选岗位 → 写指令 → 一键下发 |
| **台账** | 每一次调用的时间、岗位、token、花费、产出、问题 |

> 控制台只监听 127.0.0.1，外部访问不到。
> 它是**指挥台不是执行器**——浏览器只负责收单，真正调用 API 的是 Python 进程，
> 这样禁区拦截、三道人工闸、成本记账才不会被绕过。

### 终端版（随手看一眼）

```bash
python run.py board
```

输出长这样：

## 二、下达指令：三种方式

### 方式 1：网页派活台（最省事）

1. `python run.py console`
2. 点「派活台」标签
3. 下拉选岗位 → 上面会显示这个岗位的典型用法
4. 在文本框写清楚要干什么
5. 选模型档位 → 点「下发指令」

### 方式 2：命令行（快）

```bash
# 先看看有哪些岗位、每个能干什么
python run.py assign --list

# 下达指令
python run.py assign A07 "帮我写一篇关于『AI 办公提效』的文章，1500字，面向不想学代码的职场人，结尾引导加微信" --use-kb --save 我的文章.md
```

常用参数：

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `--use-kb` | 自动挂载知识库上下文 | 让员工先读你的资料再干活。**大部分时候都该加** |
| `--save 文件名` | 产出存成文件 | 想留下产物 |
| `--tier scan` | 最便宜（flash 模型） | 找素材、整理资料、列清单 |
| `--tier create` | 正常（默认） | 写稿、改稿、生成内容 |
| `--tier judge` | 最强（v4-pro + 思考） | 质检、把关、判断。慢且贵，但结论准 |
| `--temp 0.9` | 创造力（0-1） | 想要更多花样就调高，要稳就调低 |

### 方式 3：跑整条链路（最省事）

不知道该派谁的时候，直接跑链路——8 个岗位自动接力：

```bash
python run.py today --topic "你的选题"
```

链路顺序：
```
A03 情报 → A04 素材 → A05 选题 → A07 撰稿 → A10 质检 → A08 改稿 → A09 去AI味 → A11 适配
```

跑完读 `data/outputs/20261028/7_A09_去AI味定稿.md`，填【待补】，勾 AI 声明，手动发布。

## 三、怎么把指令写清楚（返工少的关键）

一条好指令包含四要素：

```
做什么 + 给谁看 + 多长/什么格式 + 有什么不能碰
```

**反例**：
> 写个关于 AI 的文章

**正例**：
> 帮我写一篇关于「工业机器人编程资料包里该放什么」的文章，1500-2500 字，
> 面向刚接手机器人项目的工程师，要能看懂。
> 结构：先说踩过的坑，再给清单，最后提醒版权红线。
> 不要出现 FANUC/ABB/库卡商标，不要承诺「保证学会」。
> 涉及我自己的项目经历的地方用【待补：xxx】标出来，不要编造。

员工**不会自己知道**你的身份、你的客户、你的禁忌。所以要写出来。

## 四、状态和偷懒指数是怎么判的

所有判定都基于真实台账 `data/logs/telemetry.jsonl`，规则写在代码里，可复算。

### 状态

| 状态 | 含义 |
|---|---|
| 干活中 | 最近 10 分钟内有调用 |
| 刚完工 | 最近 24 小时内有调用，且无异常 |
| 待命 | 超过 24 小时有调用，之后没动 |
| 未开工 | 从来没被调用过（**不是偷懒，是还没派活**） |
| 异常 | 最近一次调用失败 |

### 偷懒指数（0-100）

**看的是最近一次干得怎么样，不是历史累加**——同一个问题重复 10 次不代表现在偷懒 10 倍。

| 信号 | 加分 |
|---|---|
| 最近一次产出低于该岗位预期下限 | +40 |
| 产出含【待补】/【待填】标记（把活推回给你） | +25 |
| 输出疑似被截断 | +25 |
| 最近一次调用失败 | +50 |
| 最近 3 次里有 2 次以上失败 | +30 |
| 产出未落盘（可能空转） | +20 |

> **「含待补标记」不等于员工偷懒。**
> 实际上这是**好员工的表现**——它知道自己缺什么（你的真实经历），标出来而不是编。
> 真正该担心的是：产出过短、失败、截断、空转。

## 五、常见问题

**Q：状态墙显示全是「未开工」？**
A：还没跑过真实调用。跑一次 `python run.py today` 或 `python run.py assign A07 "..."` 就有数据了。

**Q：控制台页面打不开？**
A：端口被占了。换端口：`python run.py console --port 8900`。

**Q：网页派活点了没反应？**
A：派活单要 Python 进程去执行。如果控制台是用 `--no-open` 起的，它在后台轮询；
如果是直接关了终端，进程就没了。先确认 `python run.py console` 还在跑。

**Q：token 涨得比预期快？**
A：开思考模式时，推理链也按输出价计费。用 `--tier scan` 做粗活，
`--tier judge` 只用在真需要判断的地方。跑 `python run.py cost` 看每个岗位的预估花费。

**Q：产出文件在哪儿？**
A：`data/outputs/<日期>/`。链路产物在日期目录，单次 assign 产物在 outputs 根目录。

# 一人AI公司 · 能力组合说明

> 回答一个问题：**本地、Docker、Coze 三样都有，哪些该单独做，哪些该组合？**
>
> 结论先说：**不是三选一，是分四层，各管一段。**
> 现在真正跑通的是「本地控制台」这一层，其余三层是可选增强，不是必需。

---

## 一、一句话结论

```
能写代码确定的活  →  本地 Python（零 Token、离线、只有它能碰你的文件）
要模型判断的活    →  统一走 new-api 网关（一个 Key 管所有模型）
要定时自跑/对外   →  Coze（云端，不碰本地文件）
想拖拽看流程      →  Dify（可选，内部编排用）
```

**你现在缺的不是功能，是把已经跑通的东西接上模型网关。**
本地控制台已经能一键成稿、出图出视频、排版推草稿箱——**这些全都不需要 Docker 和 Coze**。

## 三、分工原则：三条判定规则

拿到任何新需求，按这三条判一次，就知道该放哪层：

### 规则 1：能用代码确定算出来的，绝不烧 Token

排版、出图、切图卡、生成视频、整理文件、建索引、备份、算费用——
这些**结果唯一确定**，用模型算就是浪费钱还可能算错。

> 本地控制台已经做到了：**出图出视频 0 Token**，只有写稿和质检走模型。
> 这就是为什么一篇完整文章只要 ¥0.21。

### 规则 2：需要判断力的活，才走模型

选题、写稿、质检、去 AI 味、改写——这些是"没有唯一答案"的活，交给模型。

> 关键：模型**只产出文字**，产出文字之后的排版/配图/归档仍然回本地。
> 边界画在这里：**AI 负责内容，本地负责形式。**

### 规则 3：需要定时自跑、需要对外、需要生态的，走云端

| 需求 | 放哪 | 为什么 |
|---|---|---|
| 每天早上自动跑情报采集 | **Coze 定时任务** | 本地电脑不开就停了 |
| 文章发到公众号 | 本地或 Coze | 本地已有草稿箱 API |
| 把技能包挂到扣子商店卖 | **Coze** | 只有扣子有商店 |
| 每天自动整理一次工程目录 | **本地规划师** | 只有本地能碰你的文件 |
| 拖拽可视化编排流程 | Dify | 给人看流程图用的 |

Coze 让模型干活 → 结果落到本地 → 本地排版出图 → 本地推公众号草稿箱。

## 六、推荐组合方案

### 方案 A：只做本地（当前状态，已够用）

**不碰 Docker、不碰 Coze。**
一个 `03_启动控制台.bat` + 一个网页 = 完整的「AI 员工自动干活」闭环。

- 优点：零维护、零额外成本、文件不出本机
- 缺点：电脑不开就停；没有定时任务；图像只有本地渲染（模板化）
- **适合**：先把内容流水线跑出 10 篇，验证选题和风格

### 方案 B：A + 接模型网关（✅ 已完成）

**做了一件事：把模型调用从直连 DeepSeek 改成走本机 new-api 网关。**

```
控制台 (①)  ──请求──>  new-api (②)  ──分发──>  DeepSeek / 未来任何模型
     ↑                                                      │
     └────────────── 计费/审计统一在网关 ────────────────────┘
```

**已经配好的（2026-10-29 实测通过）：**

| 项 | 状态 |
|---|---|
| 渠道 #1 的真实 DeepSeek Key | ✅ 已填 |
| 网关访问令牌「一人AI公司」 | ✅ 已建（无限额） |
| 自用模式（免逐模型配价） | ✅ 已开 |
| 模型路由 `deepseek-flash` / `deepseek-v4-pro` | ✅ 已注册到渠道 1 |
| 模型映射 | ✅ `deepseek-flash→deepseek-chat`、`deepseek-v4-pro→deepseek-reasoner` |
| 工程侧改动 | ✅ **只改 `base_url` + `api_key` 两个顶层键，模型名一个字没动** |
| 单角色调用实测 | ✅ 经网关返回正常内容（982 tokens，台账已记） |

**你得到三样东西：**
1. **加模型不用改代码** —— 以后接图像模型、Claude、GPT，只在网关后台加渠道
2. **所有调用有台账** —— 网关记录每次调用的模型/Token/花费
3. **一个 Key 保护** —— 工程里不用再存各家 Key

**控制台怎么看**：打开「📊 概览」，最上面「🔌 模型调用通道」会显示
「模型网关 new-api」+ 绿色「网关」标签。改成直连或网关，页面立刻能看出来。

**⚠️ 一个副作用要知道**：网关开了自用模式后**不再记调用日志**（自用模式就是不计费的意思）。
所以**费用台账以工程内的 `data/logs/telemetry.jsonl` 为准**——「🧑‍💼 状态墙」和「📊 概览」的花费数字都读它，不受影响。

**⚠️ 网关挂了怎么办**：模型调用会全部失败（控制台、出图、排版这些本地功能不受影响）。
一分钟回退：

```bash
# 恢复直连（工程里备份的配置）
cp 08_可运行系统/config/config.json.bak_before_gateway 08_可运行系统/config/config.json
# 然后重启控制台
```
或直接改 `config/config.json` 两个顶层键：
```json
"base_url": "https://api.deepseek.com",
"api_key": "<原来的 DeepSeek Key>"
```

**一键重跑接入**（如果你在网关后台手动改乱了）：
```bash
python 工具脚本/接入模型网关.py            # 干跑，看现状
python 工具脚本/接入模型网关.py --apply    # 重新配置（自动备份数据库）
```

### 方案 C：B + Coze 定时（最终形态，等内容跑顺了再上）

**本地负责"出成品"，Coze 负责"按时开工"。**

```
Coze 定时任务（每天 07:00）
   └─ 调用工作流：选题 → 写稿 → 质检
   └─ 结果通过 Webhook 回调本地控制台
        └─ 本地：排版 → 出图出视频 → 生成发布包
        └─ 本地：推公众号草稿箱（等你人工确认）
```

- ⚠️ **注意**：这条链路要你自己写 Coze 工作流，本地控制台目前没有做 Webhook 接收端
- ⚠️ **注意**：Coze 的定时在你没登录控制台时也跑，但**产出回传本地需要本地服务在线**
- 建议等方案 B 跑通、模型调用统一了再上这一步，否则要配两套 Key

### 方案 D：把 Dify 也用上（可选，不推荐现在做）

Dify 的价值是**给人画流程图看**。你的流程已经有网页可视化了，Dify 会变成第二套编排器——**三套编排 = 三倍维护**。

真要用，只用在一个地方：**需要一个别人能打开就能用的内部页面时**（社区版不能发布对外链接，只能内网访问）。

## 八、明确不要做的事

| 别做 | 为什么 |
|---|---|
| ❌ 把 Dify 和 Coze 都当主控台 | 三套编排器 = 三倍维护，还对不上账 |
| ❌ 把产出目录交给云端 | 云端碰不到本地文件，产出还得搬回来 |
| ❌ 用 Dify 社区版做对外发布 | `enable_app_deploy=false`，发不出去 |
| ❌ 现在就去抠 new-api 之外的容器 | geek/hermes/openclaw 与本项目无耦合 |
| ❌ 一次性全接 | 一次接一层，每层单独验证 |

## 九、验证方法

改完之后，用这三条自查（都能在网页上做）：

1. **网关是否生效** → 控制台「📊 概览」看 API 地址是不是变成了 `127.0.0.1:3001`
2. **台账是否统一** → 控制台「🧑‍💼 状态墙」看调用数与费用是否与网关后台对得上
3. **产出是否没坏** → 控制台「⚡ 一键成稿」跑一篇，看是否仍能产出 22 个文件

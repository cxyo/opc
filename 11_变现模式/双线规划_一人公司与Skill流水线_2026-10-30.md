# 双线规划：一人公司 × Skill 流水线（2026-10-30 定稿）

> 决策人拍板的两件事：
> 1. **网页端演示版 = 免安装包 + 公网链接，两者都要。**
> 2. **首批不铺行业包，先做通用版「企业知识库 + 老板的 AI 员工」跑起来，先看到效果，再增加功能。**
> 3. **变现：Skill 单卖 + 行业包溢价。**
>
> 本文档是执行依据。所有判断都带数据出处，不写"值得关注"。

---

## 一、为什么把顺序倒过来（原来想先铺行业包）

调研数据（2026-10-30 联网核实）：

| 数据 | 数值 | 出处 |
|---|---|---|
| 国内企业 AI 智能体普及率 | 2025 年 22% → **2026 年 40%** | CSDN 行业调研 |
| 中小微企业普及率同比增幅 | **62%**（最快） | 同上 |
| 渗透率 > 50% 的行业 | 工程咨询、餐饮连锁、出海电商、教育、文旅 | 同上 |
| 企业选型首要诉求 | 安全能力 28% → **45%**（第一诉求） | 同上 |
| 中小微企业（<100人）核心诉求 | **开箱即用、不需要复杂部署** | 同上 |
| AI Agent 用例渗透率第一 | **客服自动化 69%** | First Page Sage 2026 |
| 其后 | 供应链 59% / IT监控 56% / 软件开发 55% / 营销 47% / 销售线索 40% / 财务 32% | 同上 |

**推论：**

1. **增速最快的是中小企业，而他们要的是"开箱即用"。**
   铺 15 个行业包 = 做 15 套定制 = 交付周期长、客户用不上。
   **一个通用版打透，比 15 个半成品行业包强。**

2. **"让老板的 AI 员工跑起来"是最短的见效路径。**
   老板打开 → 丢进自己的资料 → AI 员工回答他关心的问题 → 当场看到效果。
   这条链路不需要先理解你的行业包体系。

3. **安全是客户的第一诉求（45%），而你手上有别人没有的东西：85 条平台红线 + 禁区清单。**
   这是通用版最该打的差异化——**不是"功能多"，是"不闯祸"。**

4. **行业包不是不做了，是要等通用版验证后再补。**
   行业包的价值在于**溢价**，不在于**覆盖**。没有通用版做底，单独卖行业包是在给客户做一次性定制。

## 二、规划一：一人公司（通用优先，行业随后）

### 2.1 产品分层

| 层 | 名称 | 形态 | 谁买 | 价格带 |
|---|---|---|---|---|
| **L0** | **演示版** | 公网链接 + 免安装包，客户上传 3-5 份自己的资料就能试 | 免费试用 | ¥0 |
| **L1** | **正式版** | 源码 / 免安装 / Docker 三选一，24 岗位 + 6 行业包 + 看板 + 交付包 | 中小企业主 | ¥1,999 ~ ¥4,999 首年 |
| **L2** | **行业版** | 行业包（岗位提示词 + 行业知识库 + 交付物清单 + 步骤链） | 特定行业 | ¥6,999 ~ ¥19,999 |
| **L3** | **定制/旗舰版** | 驻场对接、私有化部署、专属岗位开发 | 大客户/政企 | 面议 |

**L0 是全部漏斗的入口。** 演示版必须做到：**不注册、不填表、点开就能试**。

### 2.2 L0 演示版必须有的三件事

1. **客户资料直接可用**：拖进来或指定目录 → 自动入库 → 立刻能问
2. **一个问题就见效**：老板问自己业务里的真问题 → AI 用他的资料回答 → **答案带出处**
3. **过程可见**：看板实时显示这次问答走了哪几步、命中了哪些文档、token 花了多少

> 第 3 条是你独有的。上一轮对标 63 条视频里，**没有一条展示真实运行画面**。

### 2.3 首批"必用、常用、稳定"的 AI 员工

按调研用例渗透率 + 客户第一诉求筛，**只做 6 个**，都围绕"老板的 AI 员工跑起来"：

| 编号 | 岗位 | 干什么 | 调研依据 | 现状 |
|---|---|---|---|---|
| **新增 A25** | **企业知识库管理员** | 把老板的资料（产品手册/报价单/SOP/合同模板/FAQ）变成可问的知识库 | 通用版核心入口 | **待建** |
| A15 | 客服应答员 | 买家问什么都能答，答不了转人工 | 客服用例 69%，全局第一 | 已有，需接知识库 |
| A07 | 公文/方案起草员 | 通知、方案、报价单初稿 | 文档起草 60%+ | 已有 |
| A13 | 报价与详情页员 | 出带"不适合谁"的报价与方案 | 文档/报价刚需 | 已有，需接知识库 |
| A10 | 合规质检员 | 发出前查红线（平台红线 + 禁区清单） | **安全诉求 45%，第一诉求** | 已有，85 条红线 |
| A03 | 情报雷达员 | 每天抓同行动态，只留跟你定位相关的 | 内容/代运营刚需 | 已有 |

**关键点：A25 是新增的，其余 5 个已有。**
现有 24 个岗位是内容生产向的（写稿、选题、发布），**通用版缺一个"管知识库"的岗位**——而它恰恰是老板最先感知到价值的那一个。

### 2.4 演示版要跑的"完整流程"（一条就够）

```
老板上传 3 份资料（产品手册.md / 报价单.md / FAQ.md）
   ↓
A25 企业知识库管理员：建索引、列出每份文档能回答什么
   ↓
A15 客服应答员：用这批资料回答 3 个真实问题，答案带出处
   ↓
A10 合规质检员：检查这 3 个答案有没有踩红线
   ↓
看板：全程步骤 / 命中文档 / token / 成本 / 失败与重试
```

**一条流程跑通，客户当场看到"我的东西变成我的 AI 员工了"。**
这比铺 15 个行业包更快产生第一笔成交。

### 2.5 行业包：后置，但已排好序

调研给的渗透率 > 50% 的行业：**工程咨询、餐饮连锁、出海电商、教育、文旅**。
加上你的现有优势：制造业（机器人/头盔/卡诺普）。

**建议顺序（等 L1 跑通后，按"我能不能拿到真实资料"排，不按市场规模排）：**

| 优先级 | 行业包 | 为什么这个顺序 |
|---|---|---|
| 1 | **餐饮连锁** | 资料高度标准化（菜单/ SOP / 卫生规范 / 排班），一个人能写完一套；决策链短 |
| 2 | **工程咨询** | 渗透率 > 50%，且招投标线索筛选是明确实例（2 名员工/年成本 20 万的测算） |
| 3 | **出海电商** | 已有 ecommerce 包可扩厚；内容/客服/选品三合一，客单价高 |
| 4 | **教育/文旅** | 渗透率 > 50%，材料复用度高 |
| 5 | **制造业深化** | robotics/helmet/crp-yl 已有，只需加知识库厚度 + 岗位提示词 |

> **原则：先做"资料标准化程度高"的行业，不做"客户最有钱但资料最乱"的行业。**

## 三、规划二：抖音内容 × Skill 流水线

### 3.1 链条全貌

```
        ┌──────────────── 每天自动 ────────────────┐
        │                                          │
   GitHub 爆火项目雷达  ──▶  下载到本地  ──▶  README→SKILL.md 自动转换
   （A03 情报雷达改造）                            │
        │                                          ▼
        │                                    Skill 展示页（商品页）
        │                                          │
        └──────▶ 录屏 + 文案 + 分镜 ──▶ 抖音/视频号 ◀───┘
                          （内容获客）        （转化）
```

**关键：展示页既是商品页，也是获客页。**
客户刷到视频 → 搜到/点进展示页 → 试用 → 买单个 Skill（¥29-99）或升级行业包/正式版。

### 3.2 为什么这条路值得做

对标数据（第二批 63 条视频实测）：

| 事实 | 数据 |
|---|---|
| GitHub 项目分享类内容的平均转发/点赞 | **10.9**（63 条里 33 条是这类） |
| 全批平均转发/点赞 | 10.79 |
| 收藏/点赞 > 2 的占比 | **58/63** |
| WorkBuddy 生态类内容转发/点赞 | **16.5**（全部分类最高） |
| 最高转发/点赞的单条 | 25.36（方格动态·先接住情绪再给下一步） |

**GitHub 项目分享是这块流量池里最稳的选题类型**，而且它天然带"技能"属性——观众看的是"这个我能不能用"，跟你的商品是同一件事。

### 3.3 「GitHub 项目雷达」AI 员工的设计

**已有零件**（不要重写）：

| 能力 | 现有实现 |
|---|---|
| 情报分类 → 落到哪个岗位 | `staff/radar.py`（12 类关键词判定 + 红线拦截 + 排序） |
| 视频号抓取 | `staff/tools/fetch_sph.py` |
| 岗位说明书 → SKILL.md 包 | `07_AI员工/tools/skill_pack.py`（含 clawhub.json / README / 安装说明 / 定价表） |
| 展示页数据源 | `05_产品交付/Skill包/`（已有 22 个包 + zip） |

**要新做的**：

| 组件 | 说明 |
|---|---|
| `staff/github_radar.py` | 每天抓 GitHub Trending + 按 star 增速排序 + 中文可用性打分 → 候选清单 |
| `staff/tools/repo_to_skill.py` | 克隆仓库 → 读 README/脚本 → 生成 SKILL.md + clawhub.json + README + 安装说明 + zip |
| `staff/tools/skill_gallery.py` | 扫描 Skill包/ 目录 → 生成展示页数据（名称/定价/适合谁/不适合谁/一句话效果/下载链接） |
| 展示页 | 单文件 HTML，静态可发布，点开即用 |

### 3.4 README → SKILL.md 的转换边界（必须诚实）

**能自动做**（占价值 80%）：
- 抓 README → 提炼"这个工具干什么、怎么装、怎么用、常见坑"
- 生成 SKILL.md 的 frontmatter（name / description / 触发条件）
- 生成 clawhub.json（定价、作者、版本）
- 生成 README 落地页与安装说明
- 打成 zip，直接进展示页

**做不了，必须人工过一遍**：
- 脚本是否真的能跑（要试装）
- 依赖是否有坑（API key、付费墙、平台限制）
- 中文输出质量（大多数是英文项目）
- **能不能包装成"给这个岗位用"**——这才是值钱的，通用 README 不是商品

> **铁律**：自动转换出来的包**默认是"待审"状态**，不进展示页的"已上架"。
> 上一轮对标分析里的教训照搬：**忠于原文，没验证的标"待查"，不编造**。

### 3.5 商品化的现实判断（说在前面）

| 风险 | 事实 | 对策 |
|---|---|---|
| Skill 复制成本为零 | 客户买一次就能转发给所有人 | Skill 是**入口不是利润**：走 ¥29-99 单卖拉新，**利润放行业包和正式版** |
| 官方建议 ¥5-15 测需求 | WorkBuddy 开放平台 2026-10 开放，收 1% 服务费 | 单卖定价**降到 ¥9.9-19.9 测需求**，让 ¥29-99 的位置留给"质量保证 + 含知识库"的增强版 |
| 自动转换质量参差 | README 质量 ≠ 可用性 | 全部进"待审"，人工过一遍才上架 |
| 平台合规 | 不能承诺"保证爆款""保证收录" | 沿用已有 85 条红线；**绝对化承诺一律不写** |

**正确的商业结构**：

```
Skill 单卖 ¥9.9-19.9   ← 引流（获客 + 验证需求）
Skill 增强版 ¥59-99    ← 含知识库 + 行业适配（有人买就做）
行业包 ¥6,999+         ← 利润
正式版 ¥1,999-4,999    ← 利润
```

## 四、两条线怎么咬合

| | 抖音/视频号内容 | 一人公司产品 |
|---|---|---|
| **获客** | 每天一个 GitHub 项目（录屏） | 演示版 L0 |
| **承接** | Skill 展示页 | 演示版 → 正式版 |
| **交付** | Skill 包（自动发货） | 免安装包 / Docker / 源码 |
| **升单** | 展示页里的"升级到行业版"入口 | 行业包 |
| **共同资产** | Skill 打包器、Skill 展示页、红线清单、作战看板 | 同左 |

**唯一要守住的原则：内容不能是纯搬运。**
对标 63 条里最高转发那条（25.36）的结构是「**先接住情绪，再给下一步**」——它给的是判断框架，不是项目介绍。
所以你的视频脚本必须是：**"这个项目能干什么" + "什么人不该用它" + "我已经把它变成一个可安装的 skill"**。第三句才是你的差异化。

- [ ] L0 免安装演示包（客户只带资料就能试）

### 第 7-10 周：内容流水线 + 行业包

- [ ] 抖音录屏流水线（取项目 → 出文案分镜 → 成片）

### 第 11-13 周：变现与复盘

- [ ] 定价实测（Skill 单卖 ¥9.9-19.9 起测）

## 七、红线（沿用已有禁区清单，不新增）

1. **不承诺"保证爆款/保证收录/保证通过审"** —— 违反平台红线，已在 85 条里
2. **不把自动转换的 Skill 直接上架** —— 未验证的可安装性 = 退款和差评
3. **不编造客户案例和交付数据** —— 唯一可用的数字是实测的：0.66 秒、¥0.1406、73,936 token、18 步、24 岗位、6 行业包
4. **不做群控、批量私信、站外导流** —— 已有禁区清单覆盖
5. **客户上传的资料不出本机** —— kb.py 本地检索天然满足，写进卖点

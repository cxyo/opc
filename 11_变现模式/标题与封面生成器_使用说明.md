# 标题与封面生成器 —— 把 76 条对标视频变成可执行代码

> 工具：`08_可运行系统/tools/title_engine.py`
> 调研依据：`03_知识库/wiki/07_选题与素材/标题句式库.md`、`对标分析_2026-10-30_第二批63条视频.md`

---

## 一、为什么要有这个工具

76 条视频号链接全部抓取、四分类归档、转发率/收藏率逐条算过，
结论写进了知识库。**但结论停在文档里 = 没有用。**

之前的实际情况：
- 抖音脚本的钩子只有一句写死的话（`这个 GitHub 项目已经 N 星了…`）
- 封面永远写「按 T3 实拍型模板」
- 公式 A~H、模板 T1~T4 全在文档里躺着

现在这些结论变成了 `title_engine.py` 里的两张表，
每个 Skill 包生成时自动带出**候选标题 + 封面方案 + 画面清单**。

## 二、用法

```bash
# 看当前系统的真实硬指标
python 08_可运行系统/tools/title_engine.py

# 给某个包生成候选标题
python 08_可运行系统/tools/title_engine.py
```

流水线里已经自动接上 —— 每个包生成时，
`抖音脚本.md` 开头就是候选标题，`SKILL.md` 里也有封面建议。

## 五、三条不能破的规矩

### 1. 只用实测数字

所有数字都实时采集，**拿不到就写「未获取」，绝不编**：

| 数字 | 来源 |
|---|---|
| 岗位数 | 数 `07_AI员工/01_Bot提示词/` 里的 `A\d{2}_*.md` |
| 行业包数 | `industry.list_industries()` —— **不是数目录** |
| token / 花费 | `data/logs/telemetry.jsonl` 聚合 |
| 部署耗时 | `交付包/_实测计时_结果.json` |

> **踩过的坑**：行业包磁盘上只有 3 个目录，但内置包有 3 个（general / ecommerce / marketing），
> 总数是 **6**。只数目录会得到错数字 —— 所以必须调项目自己的接口。

### 2. 每条标题都要能说清出处

生成的每条标题都带：公式键、公式名、依据视频、数据、验证强度。
发布时如果有人问「这标题为什么这么写」，答得上来。

### 3. 规模词不许拍脑袋

「150 套」= 25 岗位 × 6 行业包，**这是代码数出来的**。
岗位数变了，数字自动跟着变 —— 不会出现标题和产品对不上的情况。

## 六、口播稿的三段结构

工具同时把「先接住情绪，再给下一步」这个结构固化了（公式 F，转发率最高那条）：

```
【前 3 秒 · 钩子】    接住"我想找个现成工具"的念头
【第 4~20 秒 · 是什么】给硬信息，带数字
【第 21~40 秒 · 怎么用】真实命令，不美化
【第 41~60 秒 · 下一步 + 边界】说什么人不该用它 ← 这是差异化
```

**第三段的「边界」是我们的差异点**：
全批 63 条没有一条说清楚「什么人不该用它」。
别人都在讲这工具多好，我们讲清楚它的局限 —— 反而更可信。

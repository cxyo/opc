## 二、目录结构

```
03_知识库/素材库/
├─ 台账.json                    ← 唯一索引（程序读这个）
├─ 原始素材/
│  ├─ 视频封面/    75 张       ← 从视频号抓下来的封面原图
│  ├─ 文章原文/    75 篇       ← 资料包原文
│  ├─ 图片/                     ← 后续发图放这里
│  ├─ 链接/                     ← 后续发链接存这里
│  └─ 文字片段/                 ← 后续粘贴的文字存这里
└─ 学习成果/      90 份         ← 每条素材一份 Markdown，可直接看
```

**为什么要分「原始素材」和「学习成果」两个区**：
原始件保持原样（可追溯），结论单独放（可阅读、可交接）。
两者分开，才不会出现"改结论时不小心改了原文"。

## 三、网页上怎么看

控制台 → 📚 素材库 页签：

1. **顶部统计** —— 素材总数 / 已用 / 已学 / 待学 / 吸收率
2. **学习进度条** —— 四态分布（绿=已用、浅绿=已学、黄=学习中、灰=待学）
3. **按类型统计** —— 各类型条数 + 原始文件数
4. **筛选栏** —— 搜关键词 / 按类型筛 / 按状态筛
5. **素材卡片** —— 封面图、标题、作者、日期、互动数据、状态徽章、
   以及最关键的「**已用：xxx / 效果：xxx**」或「尚未用上 —— xxx」
6. **点卡片 → 详情抽屉** —— 主要内容 / 值得借鉴 / 用在哪·效果 / 尚未用上的部分
7. **点「✍️ 改写成我们的文案」** —— 立刻出标题候选 + 口播稿 + 封面方案

## 五、怎么加新素材

### 加视频链接（批量）

```bash
cd 08_可运行系统/tools
python fetch_sph.py --file ids_new.txt --append --cover
```

然后重建台账：

```bash
cd 08_可运行系统
python tools/build_material_ledger.py --sync
```

### 加文章 / 图片 / 链接

把文件放进 `03_知识库/素材库/原始素材/` 对应子目录，然后：

```bash
cd 08_可运行系统
python tools/build_material_ledger.py --sync
```

（脚本会自动识别类型、抽标题、算摘要、打主题标签）

### 手动补学习结论

编辑 `台账.json` 里对应条目的这些字段：

```json
{
  "值得借鉴": "这条的结构值得学",
  "用在哪": "具体落到了哪个文件/代码位置",
  "效果": "起什么作用",
  "待用": "还有哪些可挖的、为什么还没用",
  "学习状态": "applied"
}
```

改完跑一次 `--sync`，会同步生成 `学习成果/` 下的 Markdown。

## 六、改写引擎怎么用

```bash
cd 08_可运行系统

# 看有哪些素材可改写
python tools/rewrite_material.py --list

# 改写某一条
python tools/rewrite_material.py v_AMsMoY5KBF
```

产出三件套：

1. **标题候选**（每条标注公式 + 依据出处 + 验证强度）
2. **口播稿**（按公式 F 的四段结构，每段标依据）
3. **封面方案**（按 T1~T4 选型 + 画面清单 + 禁忌）

### 两条硬规矩

**一、只借结构，不抄内容。**
从素材里取的是「公式 / 版式 / 结构」这些**方法**，
不是它的观点、案例、原句。这既是底线，也是防搬运。

**二、只用实测数字。**
岗位数、行业包数从代码实时数；token 从 telemetry 读；
部署耗时从实测脚本读。拿不到就写「未获取」，不编。

## 八、常见问题

**Q：为什么"已学"比"已用"多？**
已学 = 我读懂并提炼了要点；已用 = 这个结论已经落到具体文件里。
中间那一步是"知道了但还没用起来"——这部分正是待用清单。

**Q：吸收率 71.1% 是怎么算的？**
（已学 + 已用）÷ 素材总数。已用也包含在已学里（因为用之前肯定学过）。

**Q：视频本体没抓到，怎么分析？**
微信预览页在设计上只下发封面和文案，不下发视频流。
所以分析只基于元信息 + 封面实拍，**不做任何推测**。
需要口播稿/分镜的深度分析，得人工补料。

**Q：改写出来的标题能直接用吗？**
结构可以直接用，但**数字必须自己复核一遍**。
引擎用的是实时采集的数据，但你发布前应该确认当时的岗位数、
行业包数、token 成本还是这些值。

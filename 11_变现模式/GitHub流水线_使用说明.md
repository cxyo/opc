# GitHub 全自动流水线 · 使用说明

> **一条命令跑完：搜索 → 下载 → 做 Skill 包 → 出抖音脚本 → 审核**
> 生成时间：2026-10-31 ｜ 配套代码：`08_可运行系统/tools/`

---

## 一、为什么要有这条流水线

拆开卖不成立：

| 只做这个 | 问题 |
|---|---|
| 只转 Skill | 客户不知道这东西能干什么，转化不了 |
| 只做视频 | 有流量但没有商品承接 |
| 只做 Skill | 有商品但没有流量来源 |

**所以一个 GitHub 项目进来，必须走完整条链，产出四样东西：**

```
① Skill 包    SKILL.md + clawhub.json + README + 安装说明   → 商品
② 抖音脚本   可直接开录的口播文案 + 分镜                    → 流量
③ 审核报告   哪里能用、哪里不能用、卡在哪                    → 防翻车
④ 源信息     原始仓库数据，可追溯                            → 查证
```

## 二、四个脚本，各管一段

| 脚本 | 作用 | 单独能跑吗 |
|---|---|---|
| `staff/github_radar.py` | 扫 GitHub 找最近爆火的 AI 项目并打分 | ✅ |
| `tools/repo_to_skill.py` | 单仓处理：下载 → 做包 → 写脚本 → 审核 | ✅ |
| `tools/auto_pipeline.py` | **编排器**：搜索 → 逐仓处理 → 出日报 | ✅ |
| `tools/publish_gate.py` | 上架闸门：待审 → 已上架 | ✅ |
| `tools/skill_gallery.py` | 生成 Skill 展示页 | ✅ |

**日常只需要记两个命令：**

```bash
# 跑一轮流水线（自动找项目、自动做包、出日报）
python 08_可运行系统/tools/auto_pipeline.py

# 看看哪些能上架，然后上架
python 08_可运行系统/tools/publish_gate.py --list
python 08_可运行系统/tools/publish_gate.py --publish <名字> --confirm
```

## 三、完整命令参考

### 3.1 流水线编排器

```bash
python 08_可运行系统/tools/auto_pipeline.py [选项]
```

| 选项 | 说明 | 默认 |
|---|---|---|
| `--days N` | 雷达看最近几天 | 7 |
| `--top N` | 一轮处理几个仓 | 5 |
| `--min-stars N` | star 门槛 | 20 |
| `--min-score N` | 雷达评分门槛（0=不限） | 0 |
| `--repo owner/repo` | 指定仓库，可重复；给了就跳过搜索 | — |
| `--scan-only` | 只搜索，不做包 | — |
| `--no-llm` | 不调模型，纯模板（快、稳、免费） | — |

**典型用法：**

```bash
# ① 只看看最近有什么新项目，不浪费时间做包
python 08_可运行系统/tools/auto_pipeline.py --scan-only

# ② 每天跑一次，只处理评分高的
python 08_可运行系统/tools/auto_pipeline.py --top 3 --min-score 60

# ③ 刚看到一个项目，直接处理
python 08_可运行系统/tools/auto_pipeline.py --repo anthropics/claude-code

# ④ 断网/不想花钱，纯模板跑
python 08_可运行系统/tools/auto_pipeline.py --no-llm
```

### 3.2 单仓处理

```bash
python 08_可运行系统/tools/repo_to_skill.py owner/repo [--no-llm]
```

### 3.3 上架闸门

```bash
python 08_可运行系统/tools/publish_gate.py --list
python 08_可运行系统/tools/publish_gate.py --check <名字>
python 08_可运行系统/tools/publish_gate.py --publish <名字> --confirm
python 08_可运行系统/tools/publish_gate.py --publish-all --confirm
```

### 3.4 展示页

```bash
python 08_可运行系统/tools/skill_gallery.py [--open]
```

输出：`07_AI员工/05_自动生成技能/展示页.html`（双击即可打开）

## 四、三条铁律

### 铁律一：源码不落盘

下载的仓库源码**只在内存里处理**，不写磁盘。

理由很实在：一次处理 10 个仓，每个仓平均 12MB，落盘就是 120MB 垃圾，
还得清理——而清理会触发批量删除拦截，流程直接卡死。
改成内存处理后，这个环节的耗时和磁盘占用都归零。

### 铁律二：自动产出默认进待审区

流水线只写 `07_AI员工/05_自动生成技能/_待审/`，**绝不自动上架**。

```
README 写得漂亮 ≠ 装得上、跑得通、对客户有用。
自动上架一次翻车，客户的信任就没了。
```

上架必须经过 `publish_gate.py` 的**三重闸门**：

| 闸门 | 检查什么 | 为什么 |
|---|---|---|
| ① 审核通过 | 审核报告"是否通过"为真 | 结构/红线/可用性/诚实性四关任一不过都不能卖 |
| ② 协议可商用 | MIT / Apache / BSD / ISC 等 | 协议不对，商用就是侵权 |
| ③ 人工签字 | 命令行必须传 `--confirm` | **闸门如果能被"顺手"跳过，那它就不叫闸门** |

### 铁律三：失败不扩散

一个仓失败只记一条，整批继续跑完；日报里如实写明哪个失败、为什么。

## 五、审核是怎么做的

审核分四关，任何一关不过都不能上架：

| 关 | 检查 | 不过的后果 |
|---|---|---|
| ① 结构完整 | 五个文件齐不齐、frontmatter 合不合法 | 客户装不上 |
| ② 红线 | 用项目自己的禁区清单扫一遍 | 真风险（封号/罚款） |
| ③ 可用性 | 有没有安装说明、有没有命令、依赖说没说清 | 客户不知道怎么用 |
| ④ 诚实性 | 有没有把"待人工确认"的东西说成确定的 | 客户预期落空 |

### 5.1 红线扫描的"适用域"分流

这是审核能不能用的关键。早先版本拿**内容发布域**的条款去扫**产品文档**，
结果 `## 绝对禁止` 里的"绝对"被判成"抖音标题党"，
`不写「100%」` 里的"100%"被判成"淘宝极限词"——
**一个合格包被判 27 处红线、0 分、不能上架**。

现在分成两个域：

| 域 | 管什么 | 扫什么 | 命中后果 |
|---|---|---|---|
| `product` | **这个软件本身能不能做**：去标识服务、洗稿工具、破解外挂、批量外呼、群发短信、金融荐股… | SKILL.md | **阻断** |
| `publish` | **发到平台的内容不能写什么**：标题党、擦边、私信导流、主图极限词… | SKILL.md / 抖音脚本 | 仅提示 |

配套三层机制（都在 `staff/kb.py`）：

| 机制 | 解决什么 |
|---|---|
| `clean_keywords()` | 过滤 `—` 这类**占位符**（"判定关键词"列写 `—` 表示本条没有自动判定关键词，不是关键词） |
| `_scope_of()` | 按适用域分流 |
| `_is_negated_context()` | **否定语境守卫**：我们自己写的 `不刷量`、`## 绝对禁止` 是合规声明，不是违规 |

**守卫的正反例**（回归测试里锁死了 24 条）：

```
✓ 判为否定（合规声明）      ✗ 判为命中（真实风险）
不批量私信、不刷量            本工具可批量私信获客
不写「保证」「100%」          帮你稳赚不赔
## 绝对禁止                   支持破解付费内容
禁止使用群控、批量私信         群控养号一体机
```

跑回归测试：

```bash
python 08_可运行系统/测试_审核守卫.py
```

**这条测试不能删。** 审核一旦失灵，流水线会把违规包放进 `_已上架/`，
那是真金白银的封号和罚款风险。

## 七、每天怎么用（建议节奏）

| 时间 | 动作 | 命令 |
|---|---|---|
| 早上 | 扫一眼有什么新项目 | `auto_pipeline.py --scan-only` |
| 中午 | 处理 3 个候选 | `auto_pipeline.py --top 3` |
| 下午 | 实机装一次 + 核协议 | 手工 |
| 傍晚 | 上架通过的 + 刷展示页 | `publish_gate.py --publish-all --confirm` |

**日报**（`11_变现模式/流水线日报/`）直接回答客户最关心的一句话：
**"你这周到底产出了什么？"**

## 八、已知的环境限制

| 限制 | 影响 | 应对 |
|---|---|---|
| `api.github.com` 会限流（403） | 元信息拿不全 | 已做降级链：API → HTML → 空；拿不到就**如实标"未获取"**，不写"数千"这类模糊词凑数 |
| `github.com` / `raw.githubusercontent.com` 不通 | 同上 | 下载改走 `codeload.github.com`（不限流、不需 token） |
| `gh` CLI 无 token | 不能用 gh 拉元信息 | 用匿名 API + HTML 降级 |
| 单仓处理约 84 秒 | 跑 10 个要 14 分钟 | 建议 `--top 3`，别贪多 |
| 429/403 偶发 | 某个仓可能失败 | 失败不扩散，日报里如实写 |

## 九、下一步人工动作（**流水线替你做不了的那部分**）

1. **实机装一次** —— README 写得漂亮不等于装得上，这条流水线替不了你做。
2. **核对原项目协议** —— MIT / Apache / BSD 才可直接商用。
3. **抖音脚本先自审一遍** —— 钩子那句是不是**你真做过**？
   没做过就别录——本系统第一号红线是「不虚构」。
4. **通过才移 `_已上架/`** —— 闸门不替你签字。

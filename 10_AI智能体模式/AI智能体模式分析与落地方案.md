## 一、这个视频讲的"AI 智能体"到底是什么

### 1.1 不是聊天机器人，是"数字员工"

他反复强调的三个特征（对照他直播大纲里的表述）：

1. **有岗位说明书** —— 不是"帮你写东西的工具"，是"内容官""质检官""交付官"，各司其职
2. **有工作流程** —— 单独一个智能体没用，能串成链路才有用
3. **有 KPI 和考核** —— 干得好不好要能评估，评估不通过要能返工

他举的例子很具体：餐饮店的"订座专员"、装修公司的"客户经理"、工厂的"生产调度员"。
都不是"AI 帮你想"，是"AI 替你在流程里站着"。

### 1.2 他的三个核心主张

**主张一：AI 是生产力工具，不是效率工具。**
> 移动互联网解决了效率和便捷性问题，但从未真正解决生产力问题。

**主张二：交付必须"重 AI + 轻人工"。**
他讲了一个案例：某亲子教育赛道头部 IP，原本人工年度陪跑定价 10 万、一年最多接 50 单、营收 500 万。
改成"10 个数字老师 + 1 个真人班主任"后，定价降到 3 万，营收冲到 3000 万。
> 你的核心价值不再是亲手做每一次交付，而是把你的思想、方法论、案例沉淀成可复制的智能体系统。

**主张三：成交不是说服，是"先看见结果"。**
> 客户上传一张素颜照，AI 立刻生成不同品相的术后效果——用户一眼看见自己变美的样子，不用销售比划。

### 1.3 一句必须警惕的话

他在一篇公开对话里说过：
> "我彻底换了赛道……你们那套全部都是**个人效率工具**。真正的企业级 AI 改造是多部门协作、跨业务流打通、**一个智能体统管企业全局**。"

**这句话对"一人公司"是成立的，对"卖服务给小客户"是不成立的。** 下面第五节会展开。

## 二、适不适合你做？分三层看

### 2.1 概念层面：适合，且你已经做完了

对比一下他说的"数字员工三要素"和你已有的 21 个岗位：

| 他的要求 | 你的现状 | 差距 |
|---|---|---|
| 有岗位说明书 | 21 份 Bot 提示词，每份含人设/开场白/建议问题/知识库/变量 | ✅ 已完成 |
| 有工作流程 | 8 步内容链路已跑通并落盘 | ✅ 已完成 |
| 有 KPI 和考核 | A10 质检官 + 71 条禁区库 + verdict_code | ✅ 已完成 |
| 能串成链路 | `run.py today` 一条命令跑完 8 步 | ✅ 已完成 |
| 能独立调用 | `run.py ask A07 "..."` | ✅ 已完成 |

**这已经不是"适不适合"的问题了——你手上这 21 个岗位，就是他说的"数字员工"。**
只是之前你把它们当"内部生产力工具"用，没当成"商品"用。

### 2.2 商业模式层面：适合，但要从"卖服务"升级到"卖货"

他的原话逻辑是：AI 进化速度极快，**定制开发会越来越不值钱**。
> "年初制作 agent 是挺复杂的事情，现在定制 agent 只需要一句话……所以 AI 越进化，客户就越不需要这些企业 AI 化服务人员了。"

这个判断**对你的项目尤其成立，而且正好指出了你的下一步**：

| | 定制服务 | 标准化商品 |
|---|---|---|
| 交付 | 每次重做 | 一次做好，重复卖 |
| 天花板 | 你的时间 | 市场 |
| 你现在的状态 | 代做服务（¥99-299） | **资料包已有，但 SKU 太散** |

所以：**你的 21 个岗位不该继续当内部工具用，应该被打包成"能上架的货"。**

### 2.3 市场层面：适合，但不是他的主战场

他讲的是**实体商家**（餐饮、零售、美业、教培）。你在这块没有优势，也没必要跟他抢。

**你的独有战场是工业/制造业的 AI 落地**——你有真实的机器人打磨工作站、力控、PLC 联动项目经验。
他带的学员是小白，你是从产线里爬出来的人。这个位置他占不了。

## 三、具体怎么做：把岗位变成 SKU

这是本次落地的核心。做法已经写进代码里了。

### 3.1 关键原则：对外不能说"智能体"

陈厂长自己说得对：卖给客户的不是"基于什么架构的智能体"，而是"你这个 SKU 的竞品分析报告，点一下自动出"。

所以对外商品名必须用**业务语言**：

| 内部岗位 | ❌ 对外不能这么说 | ✅ 对外应该这么说 |
|---|---|---|
| A03 情报官 | 情报采集智能体 | 行业热点情报周报 |
| A10 质检官 | 合规检测 Agent | 发布前合规体检 |
| A09 去AI味官 | AI 味清除器 | AI 味清除 |
| A16 GEO优化官 | GEO 智能体 | AI 搜索可见度优化 |

### 3.2 每个 SKU 必须有的七件套

已经写进 `staff/shop.py`，每一款都齐：

1. **一句话价值**（客户视角，不是功能视角）
2. **卖给谁**（具体到行业和角色，不能是"需要提效的人"）
3. **痛点原话**（用客户会说的话写，不是你的分析）
4. **交付结果**（可验收的东西，要能打勾）
5. **演示怎么做**（5 分钟内能让客户看见）
6. **交付形态与周期**（含改几轮、几天）
7. **护城河**（为什么别人抄不走）

### 3.3 当前 11 款 SKU

```
| 岗位 | 对外商品名                   | 价格                    |
| A03 | 行业热点情报周报              | ¥299/月                 |
| A05 | 选题库定制                   | ¥199 一次性 / ¥99/月    |
| A07 | 公众号长文代写               | ¥199 起/篇              |
| A09 | AI 味清除                    | ¥69/篇 或 ¥999/月       |
| A10 | 发布前合规体检               | ¥29/次 或 ¥199/月       |
| A11 | 一稿多平台适配               | ¥99/组                  |
| A13 | 商品详情页代写               | ¥299 起/个              |
| A16 | AI 搜索可见度优化            | 免费诊断 / ¥999 起一次 / ¥1,999 起每月 |
| A17 | 短视频口播稿                 | ¥99/条                  |
| A18 | 私域成交话术                 | ¥299 一次性             |
| A21 | AI 落地陪跑（工业方向）       | ¥2000 起/项目           |
```

**定价逻辑**：按客户省下的时间定价，不按 token 成本定价。
代做一篇公众号长文，客户自己写要 3 小时还改三四遍 —— ¥199 买的是时间，不是字数。

### 3.4 命令

```bash

python run.py shop A07            # 看单款完整商品卡

```

### 4.3 顺手修的一个真 bug

`staff/config.py` 里 `model_tier` 这个键**写了两次**，Python 字典后面的覆盖前面的，
导致默认配置里的 `deepseek-chat`（DeepSeek 已于 2026-07-24 弃用）会覆盖掉新的 `deepseek-flash`。

只有在 `config.json` 里恰好写了 `model_tier` 时才不受影响 —— 属于**隐性依赖配置文件**，
一旦配置文件丢了或换台机器，系统就会去调一个已经下线的模型名。

已删除重复键，现在默认值本身就是对的。

## 五、必须讲清楚的三件事（视频里没说的）

### 5.1 他的"一个智能体统管全局"不适合你现在的阶段

他说的企业级路径是：多部门协作、跨业务流打通、一个智能体统管全局。
这需要企业有完整的数据流和明确的部门边界。

**你现在是单人。** 你需要的是"一个人 + 一群数字员工"（他说的 OPC 形态），
而不是"一个智能体统管一堆部门"。

**别学他的架构，学他的商品化。**

### 5.2 91% 的项目会失败 —— 这个数字要记住

有据可查的行业数据：
- 德勤：中国 **91%** 的工业 AI 项目未达预期，**60%** 上线半年后彻底不用了
- Gartner：预测到 2027 年超过 **40%** 的 Agent 项目会被企业放弃

原因不是模型笨，是**管理**问题：权限没配、记忆会丢、系统对不上、算不出投入产出比。

**这对"卖智能体"是利好还是利空？**
短期是利空（客户会怕），长期是**大利好**（客户怕失败，所以更需要"能验收结果"的人）。
所以每一款 SKU 的"交付结果"必须**可打勾验收**，这是你区别于"卖工具"的核心。

### 5.3 他自己的业务在下滑 —— 这条更有警示价值

公开报道（新浪财经）提到，陈厂长的营收从 3 月 1200 万降到 4 月 900 万，5 月更低。
分析给出的原因之一是：
> 他的前端靠培训，后端靠给优质客户做定制化智能体。这个业务模式**太沉重太累了**。

**你现在的模式恰好相反**：轻资产、标准化、边际成本接近零。
所以他的坑你可以直接避开 —— 别走"卖课 + 重定制"这条路。

**结论：学他的商品化思路，别学他的重交付模式。**

## 六、30 天只做一件事

不是同时上 11 款 SKU。**一个月只上一个新商品**（这条铁律上次就定了，现在继续有效）。

### W1：挑一款，做深

从这 3 款里选一款（推荐第 1 个）：

1. **A10 发布前合规体检（¥29/次 / ¥199/月）** ← 推荐
   - 理由：**复购率最高**。发一次稿就要检一次，是天然的月费生意
   - 门槛最低：29 元的首次成交几乎不需要说服
   - 有真实案例可展示：拿你 21 份提示词的质检标准当场演示
2. A07 公众号长文代写（¥199）—— 客单价高但一次一单，不容易复购
3. A13 商品详情页代写（¥299）—— 闲鱼卖家付费意愿明确，但和你内容主业有点偏

### W2：做证据

- 至少 3 个真实案例（可以是熟人白送的，但必须记录前后对比）
- 一张对比图：同一段有风险的文案，体检前 vs 体检后
- 一段 60 秒演示视频

### W3：开收银台

- 货架页加「服务区」，把这 3 个 SKU 摆上去
- 微信/闲鱼/小红书简介改成"我提供 XX 服务"（不是"我分享 AI 工具"）
- 每天发 1 条实测型内容（不是 AI 资讯）

### W4：收第一单 + 复盘

- 第一单哪怕只收 29 元，**目标是拿到可公开的案例**，不是赚钱
- 交付后第 3 天问一句"用起来顺不顺" —— 这一句决定复购
- 记录：曝光 → 咨询 → 成交 三段转化率，砍掉最大的一段

# state 文件说明

> 4 个文件，是整个系统的**数据底座**。
> 没有它们，复盘官和选题官会空转。

---

## 一、四个文件的作用

| 文件 | 谁写 | 谁读 | 不写会怎样 |
|------|------|------|-----------|
| `publish_log.csv` | 你 + A11 发布官 | A14 复盘官、A12 流量官、A05 选题官 | **复盘完全失效**，永远不知道什么有效 |
| `选题池.csv` | A05 选题官 | A05 选题官、A06 拆解官 | 选题重复，永远在写同类内容 |
| `待确认清单.json` | A01 安全官、A02 政策官 | 你 | 禁区更新没人确认，规则改了不知道 |
| `对标账号清单.csv` | 你（人工填） | A03 情报官 | 抓取范围失控，或者什么都抓不到 |

## 二、publish_log.csv

### 字段说明

| 字段 | 填什么 | 谁填 |
|------|-------|------|
| `date` | 发布日期 | 自动 / 手动 |
| `platform` | 公众号 / 小红书 / 抖音 / 闲鱼 | 自动 / 手动 |
| `title` | 实际发布的标题 | 自动 |
| `topic_id` | **选题编号**，关联回选题池 | 自动 |
| `topic_type` | 选题类型（痛点型/工具型/行业结合…） | 自动 |
| `views` | 阅读/播放量 | **每天从后台导出后回填** |
| `likes` | 点赞 | 同上 |
| `comments` | 评论数 | 同上 |
| `follows` | 涨粉 | 同上 |
| `conversions` | 转化数（咨询/下单） | 手动 |
| `revenue` | 收入 | 手动 |
| `content_id` | 平台内容 ID | 自动 |
| `url` | 链接 | 自动 |
| `notes` | 备注 | 手动 |

### 为什么要 `topic_id`

**这是整个复盘体系的关键。**

有了它，你能回答：「痛点型选题的历史平均阅读是多少？工具型呢？」

没有它，你只能看到「这篇文章 500 阅读」——这个数字没有决策价值。

**编号规则**：`A05-YYYYMMDD-NN`（A05 = 选题官岗位码，例：`A05-20261028-01`）

### 怎么填

```
发布时：  发布官自动写前 12 列
每天晚上：从平台后台导出 → 贴进 Inbox → 复盘官读 → 回填 views/likes/comments/follows
成交时：  手动补 conversions 和 revenue
```

### 多久回填一次数据

**每天。** 但有个现实问题：**平台数据有延迟**，当天发的不一定当天能看到完整数据。

所以：
- 当天发布 → 次日早上回填昨天的数据
- 复盘官看到"数据未更新完"是正常的，会标注

## 三、选题池.csv

### 字段说明

| 字段 | 说明 |
|------|------|
| `topic_id` | 选题编号，同上规则 |
| `date_created` | 进入选题池的日期 |
| `title` | 选题标题 |
| `topic_type` | 选题类型（这是分类统计的关键） |
| `search_score` | 搜索价值 1-5 |
| `unique_score` | 独特价值 1-5 |
| `commerce_score` | 商业价值 1-5 |
| `material_score` | 素材准备度 1-5 |
| `total` | 四项之和（满分 20） |
| `status` | 候选 / 已选 / 进行中 / 已发布 / 已放弃 |
| `published_date` | 发布日期 |
| `performance_score` | 发布后的表现分（复盘官回填） |
| `notes` | 备注 |

### 选题类型怎么定（这决定了复盘的价值）

**不要超过 5 类。** 类型太多就统计不出规律。

推荐（针对你的定位）：

| 类型 | 说明 | 例子 |
|------|------|------|
| `行业结合` | AI × 工业机器人/制造业 | "AI在打磨工作站上真正能干什么" |
| `工具实操` | 具体工具的具体用法 | "XX工具做图文去AI味的实测" |
| `避坑纠错` | 别人踩过的坑 | "AI写作最容易出的5个错" |
| `认知观点` | 行业判断、方法论 | "为什么你的内容流水线跑不通" |
| `客户故事` | 真实案例（脱敏） | "一个中小工厂用AI改造的3个月" |

### 状态流转

```
候选 →（你选）→ 已选 →（开始写）→ 进行中 →（发布）→ 已发布 →（复盘）→ 回填 performance_score
                                                              ↓
                                                          表现好的 → 复制为新选题
                                                          表现差的 → 归档
```

## 四、待确认清单.json

### 用途

**安全官和政策官的所有产出都停在这里，等你勾选。**

这是整个系统"AI 不越权"的技术实现——AI 只能往这个文件里写建议，只有你勾了才能写进禁区清单。

### 结构

```json
{
  "待确认项": [
    {
      "id": "S-20261030-01",
      "来源": "A01安全官",
      "平台": "抖音",
      "类别": "新增收紧",
      "内容": "规则原文摘录",
      "建议标记": "🔴红线",
      "建议判定关键词": "加微信,私我,V信",
      "我的判断": "同意",
      "确认日期": "2026-10-30",
      "已写入禁区": "是"
    }
  ]
}
```

### 你的操作

```
□ 每周一跑完安全官 → 打开这个文件
□ 逐条看「我的判断」填同意/不同意/待查
□ 同意的 → 手动写入禁区清单 → 把「已写入禁区」改成"是"
□ 不同意的 → 写明理由（留给下次参考）
□ 待查的 → 去查官方原文
```

### 为什么要留「不同意」的记录

**你否掉的规则，是你的判断力记录。** 三个月后回头看，能知道哪些判断对了。

而且——如果你否掉的规则后来出事了，这就是复盘素材。

## 五、对标账号清单.csv

### 这份只能你填

AI 不能替你决定"我要对标谁"。这是定位问题。

### 需要填的账号数

**至少 10 个。** 分三类：

| 类别 | 数量 | 作用 |
|------|------|------|
| 同行（同赛道） | 4-5 | 看他们写什么、怎么写 |
| 流量博主（跨赛道） | 3-4 | 看爆款结构，不看内容 |
| 客户/潜在客户 | 2-3 | 看他们关心什么、怎么提问 |

### 关键字段说明

| 字段 | 说明 |
|------|------|
| `层级` | 头部 / 腰部 / 小众 / 精准 |
| `为什么对标` | **他有什么值得学的**（具体到某个维度） |
| `为什么我要做对标` | **我要学他什么、怎么用到自己身上** |

第二个字段是关键。只写"为什么对标"是"他做得好"，写不出第二列就说明**你不知道自己要什么**。

### 填空示例

```
某AI工具公众号,公众号,同行,腰部,"AI工具实操测评，参数对比做得细",5200,长文,每周2篇,
"参数对比表结构清晰",→学它的对比表结构，用在工业机器人选型对比上,https://xxx,
```

### 用途

这份清单是 A03 情报官的**抓取白名单**。清单外的，情报官不抓。

## 六、文件放哪 / 怎么同步

### 本地位置

```
07_AI员工/04_人类工位/state/
├── publish_log.csv
├── 选题池.csv
├── 待确认清单.json
└── 对标账号清单.csv
```

### 同步到扣子

| 方式 | 适合 | 做法 |
|------|------|------|
| **手动粘贴** | 每天几百行以内的量 | 打开 CSV 复制，粘进 Bot 的输入框 |
| **API 读写** | 数据量大或要自动化 | 扣子提供 API，GitHub Actions 也能读写 |
| **GitHub Actions** | 想让复盘全自动 | Actions 拉平台数据 → 写 CSV → 调扣子 API |

**推荐路径：先用手动粘贴。** 等你日更稳定了（20 篇以上）再考虑 API 化。

### 现有 `03_知识库` 的对应关系

| state 文件 | 和知识库的关系 |
|-----------|----------------|
| `publish_log.csv` | 是"原始数据"，进 `03_知识库/raw/` 的范畴，不进 wiki |
| `选题池.csv` | 选题官读它；表现分回写它 |
| `待确认清单.json` | 是"待办"，确认后内容进 `wiki/10_禁区/` |
| `对标账号清单.csv` | 属于 `wiki/01_情报/对标账号清单.md`，建议合并 |

## 七、每次要检查的三件事

```
□ publish_log 今天记了吗（发布后 30 秒）
□ 选题池的 status 更新了吗（候选→已选→已发布）
□ 待确认清单有积压吗（超过一周没处理说明闸门堵了）
```

## 八、一页速查

```
publish_log：发布时记前12列，每天回填数据，topic_id 必填
选题池：    选题官写，你选，类型不超过5类
待确认：    AI只写建议，你勾选后才进禁区
对标清单：  只你能填，至少10个，"我要学他什么"必须写

三不写： 不记publish_log就永远不知道什么有效
        不填topic_id复盘就没有决策价值
        不勾选禁区规则就不会更新
```

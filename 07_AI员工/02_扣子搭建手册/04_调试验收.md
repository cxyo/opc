# 扣子搭建手册 · 调试验收

> 每次改完提示词或工作流，都过一遍这份清单。

---

## 一、单个 Bot 的验收

### 1.1 四项硬指标

```
□ 输出格式与提示词里的「输出规范」完全一致
□ 没有多余寒暄（"好的""以下是""希望对你有帮助"）
□ 该标【待补】的地方标了
□ 该转人工的地方标了
```

### 1.2 通用测试用例（每个 Bot 都跑一遍）

| 输入 | 期望行为 | 不符合就查 |
|------|---------|----------|
| 正常完整输入 | 按规范输出 | 提示词是否粘全 |
| **空输入** | 明确报「缺什么」，不硬编 | 「降级行为」段是否在 |
| **半截输入** | 用已有部分做，标出缺什么 | 是否会自行补齐 |
| **超长输入**（3倍长） | 仍按格式输出，不截断关键部分 | 是否需要分步 |
| **含陷阱的输入** | 不上当 | 看该岗位的「绝对禁止」段 |

### 1.3 各岗位的专属陷阱测试

| Bot | 陷阱输入 | 期望 |
|-----|---------|------|
| A01 安全官 | 一条普通公告（无违规变化） | 输出「本期无更新」，**不编造差异** |
| A05 选题官 | 素材准备度明显不足的输入 | 不出该选题，或标 <3 分 |
| A06 拆解官 | 一篇 300 字的短文 | 提示信息量不足，换一篇 |
| A07 撰稿官 | 真实经历为空 | 文首标「⚠️ 缺真实素材」 |
| A09 去AI味官 | 风格指纹卡为空 | **明确告警**，不装作效果很好 |
| A10 质检官 | 禁区清单未加载 | **中止检测 + 告警**，不默认通过 |
| A10 质检官 | 一篇干净合规稿 | 判定【通过】，**不要为了显得尽责而挑刺** |
| A13 商品官 | 资料含「最有效」 | 只出问题清单，**不输出可上架版本** |
| A15/A18 售后 | 买家要求退款 | **强制人工** |
| A18 转化官 | 客户要求加微信交易 | 拒绝并引导回平台，不解释规则 |
| A20 短剧官 | 无法核实的痛点 | **不写**，建议换痛点 |
| A21 交付官 | 无交付SOP | 标「无标准流程，请人工补充」 |

**A10 质检官那两条最重要**——「禁区没加载就中止」和「干净稿要放行」。前者是安全逻辑，后者是可信度逻辑。质检官天天误报，你就不看它的报告了，安全逻辑也就白搭。

## 二、工作流验收

### 2.1 单节点 → 两两 → 全链

```
□ 每个节点单独跑，输出正确
□ 关键的两两组合跑通（拆解→撰稿、撰稿→质检、质检→改稿）
□ 全链跑一次，最终输出完整（正文+标题+质检报告+人工提示）
```

### 2.2 变量映射检查

**最容易出错的地方。** 逐个核对：

| 检查项 | 怎么查 |
|--------|--------|
| 输出变量名和下游引用一致 | 看工作流画布上的连线 |
| 大小写一致 | 逐字比 |
| 变量类型对（文本 vs 数组） | 看节点配置 |
| 上游节点真的输出了这个变量 | 单独跑上游，看输出字段 |

### 2.3 分支逻辑测试

**必须测全 4 条路径**：

| 质检官输出 | 期望走向 | 测了吗 |
|-----------|---------|--------|
| 【通过】 | 直接到结束，输出正文 | ☐ |
| 【打回-违规】 | 走改稿 → 去AI味 → 复检 | ☐ |
| 【打回-AI味】 | 走改稿 → 去AI味 → 复检 | ☐ |
| 【需人工确认】 | 走改稿 → 复检 → 输出待人工稿 | ☐ |

**怎么伪造质检官的输出测分支？** 临时把质检官节点换成「代码节点」，直接输出你想要的判定值，测完换回来。

## 三、发布前的系统级验收

每篇内容发布前，跑这一套：

```
□ 1. 选题官输出中，该选题未被禁区排除
□ 2. 撰稿官输出的【待补】占位符已全部处理或已确认保留
□ 3. 质检官报告 = 【通过】
□ 4. 各平台版本的 AI 声明已标
□ 5. 无站外导流暗示（含谐音/拼音/符号变体）
□ 6. 无极限词、无效果承诺、无伪造数据
□ 7. publish_log 记录已写入
□ 8. 内容确实包含你自己经历过的部分（≥20%）
```

**第 8 条是内容质量的地基，也是过 AI 检测的前提。** 这一条不过，其他都白搭。

## 四、回归测试（改提示词后必做）

改了一个 Bot 的提示词，可能影响下游。改完做：

| 改动范围 | 回归范围 |
|---------|---------|
| A10 质检官 | 重测全部 4 个陷阱用例 + 跑 1 篇完整稿 |
| A07 撰稿官 | 重测撰稿 → 质检 → 改稿 → 去AI味全链 |
| A01 安全官 | 重测「无更新」和「有更新」两种 |
| 任何岗位 | 该 Bot 的全部专属陷阱用例 |

**建议：建一个「测试稿库」，存 3 篇不同类型的稿子**（干净的、有违规的、AI味重的），改任何提示词后都拿这 3 篇跑一遍。这是最高效的回归手段。

## 五、问题定位速查

| 现象 | 最可能原因 | 处理 |
|------|-----------|------|
| Bot 开始说「好的，我来帮你」 | 提示词被改动，「风格要求」段丢了 | 补回 |
| 输出格式完全变了 | 提示词里的「输出规范」段被删 | 补回，或用 git/备份还原 |
| 引用了错误的知识库内容 | 分段切碎 / 挂了多余的库 | 检查分段，砍库 |
| 完全不引用知识库 | 关键词不匹配 | 问法改成贴近人的说法；段首补关键词 |
| 变量传过去是 undefined | 变量名不一致（大小写） | 逐字比对 |
| 每次输出都不一样 | 温度过高 | 调低温度 |
| 同一输入输出完全一样 | 温度为 0 或上下文里没有变量 | 检查温度，引入变量 |
| 质检官大量误报 | 只做了关键词匹配没做语义判断 | 检查「关键词命中必须做语义判断」这条约束在不在 |
| 质检官漏报 | 禁区条目召回不全 | 升级到「代码节点预过滤」方案 |
| 工作流跑到一半停 | 某节点报错 | 看运行日志找第一个出错的节点 |
| 分支总走错边 | 判定字符串带书名号匹配失败 | 让质检官额外输出英文 verdict_code |

## 六、月度系统复盘

每月一次，问这几个问题：

| 问题 | 看什么 | 结论落哪 |
|------|-------|---------|
| 哪些岗位在空转？ | 调用次数 vs 产出被使用次数 | 砍掉或合并 |
| 哪些提示词产出质量差？ | 人工改稿比例高的岗位 | 重写提示词 |
| 禁区清单有没有过时？ | 规则更新日志 | 安全官更新 |
| 哪些选题类型表现好？ | 案例库表现分 | 选题官加权 |
| 成本是否可控？ | 模型调用量 | 调频次上限 |

**产出：一份复盘报告，存 `../../03_知识库/outputs/`。**

## 七、一页速查

```
Bot 验收：格式 ✓ 无寒暄 ✓ 标【待补】✓ 标转人工 ✓
通用测试：正常 / 空输入 / 半截 / 超长 / 含陷阱

发布前：8项清单
回归：改提示词后跑测试稿库
```

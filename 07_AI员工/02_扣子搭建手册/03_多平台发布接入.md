# 扣子搭建手册 · 多平台发布接入

> **先说结论：Day1-30 不要接自动发布。**
> 手动复制粘贴发 30 篇，你才知道每个平台的脾气。自动发布能把违规内容瞬间发出去，代价是封号。

---

## 一、四个平台的现状与难度

| 平台 | 官方发布接口 | 个人账号可用性 | 难度 | 建议 |
|------|------------|--------------|------|------|
| **公众号** | 有（草稿箱 API） | 需认证；个人订阅号无群发接口 | 中 | 可接，但只接「生成草稿」 |
| **小红书** | 有开放平台 | 需企业主体；个人基本用不了 | 高 | 不接，用浏览器自动化 |
| **抖音** | 有开放平台 | 需企业主体 | 高 | 不接，用浏览器自动化 |
| **闲鱼** | 无 | — | — | 手动发布 |

**推荐路径：公众号接官方草稿接口（只存草稿不发布），其余三个平台用浏览器自动化或手动。**

---

## 二、公众号：官方草稿接口

### 2.1 前提

- 必须是**认证账号**（企业/个体工商户，个人订阅号拿不到）
- 后台配置：设置与开发 → 基本配置 → IP 白名单（把服务器 IP 加进去）
- 获取 `access_token`（AppID + AppSecret）

**公众号发布失败最常见的原因就是 IP 白名单没配或没加全。** 先排除这个。

### 2.2 只做「存草稿」不做「群发」

存草稿的风险：0（草稿只有自己能看到）。
群发的风险：一条违规内容发出去，影响的是真实读者和账号权重。

**建一个「存草稿」工作流：**

```
[开始] final=定稿, title=标题
   ▼
[代码节点] 组装 articles JSON
   ▼
[HTTP 节点] POST https://api.weixin.qq.com/cgi-bin/draft/add
   ▼
[结束] 输出 media_id
```

组装格式（官方文档里的结构）：

```json
{
  "articles": [
    {
      "title": "标题",
      "author": "作者",
      "digest": "摘要（120字内）",
      "content": "正文 HTML",
      "thumb_media_id": "封面图素材ID",
      "need_open_comment": 0,
      "only_fans_can_comment": 0
    }
  ]
}
```

**正文必须是 HTML。** 这是最容易卡住的地方——你的 Markdown 得先转成 HTML，而且要符合公众号的排版要求（外链、字体、行间距）。

### 2.3 正文 HTML 转换

在代码节点里做，或者用现成库（`markdown` + `html`）。但要注意公众号会过滤部分标签：

| 能用 | 慎用 | 被过滤 |
|------|------|--------|
| p / h1-h6 / strong / em / ul / ol / li / blockquote / code / pre / img / a / hr | section / div 的部分属性 | script / style / iframe / form / video 部分属性 |

**实操建议**：先做最简结构——`<p>` `<h2>` `<h3>` `<strong>` `<em>` `<ul><li>` `<blockquote>` `<img>`。别搞复杂排版，收益低、踩坑多。

### 2.4 封面图

`thumb_media_id` 必须有。流程：
1. 上传永久素材（`/cgi-bin/material/add_material`，type=thumb）
2. 拿到 `media_id`
3. 建草稿时填进去

**封面图先手动上传一次，把 media_id 记下来复用。** 自动化上传图片容易出各种问题。

## 三、小红书 / 抖音：浏览器自动化

### 3.1 为什么用浏览器自动化而不是官方接口

官方接口要企业主体 + 审核。个人做内容几乎不可能申请下来。

浏览器自动化（CDP 驱动真实浏览器）能绕过主体限制，但**要非常小心**。

### 3.2 你的技术底子

你已经有 `browser-automation-cdp` 技能（在 `~/.workbuddy/skills/browser-automation-cdp/`），它用 Chrome DevTools Protocol 驱动本机真实 Chrome/Edge。

**这是你的优势**——比通用爬虫方案稳得多，也不需要企业认证。

### 3.3 小红书发布流程

```
【前置】登录态必须留在浏览器里（扫码一次，之后复用 cookie）
   ▼
① 打开 https://creator.xiaohongshu.com/publish/publish
   ▼
② 上传图片（封面 + 正文图）
   ▼
③ 填标题（≤20字）、正文（≤1000字）、话题标签
   ▼
④ AI 生成内容声明 —— 如果用了 AI 辅助，勾选对应选项
   ▼
⑤ 点发布
   ▼
⑥ 截图记录 + 写 publish_log
```

**第 ④ 步是 2026 年的新增要求。** 小红书《社区公约2.0》（2026-01）明确要求 AI 辅助创作必须主动标识。抖音同理，且**全 AI 生成内容不可申请原创**。

### 3.4 抖音发布流程

```
① 打开 https://creator.douyin.com/creator-micro/content/upload
   ▼
② 上传视频
   ▼
③ 填标题、话题
   ▼
④ AI 内容声明（必须勾选）
   ▼
⑤ 发布
```

### 3.5 铁律（这些是封号的直接原因）

| 禁止 | 后果 | 说明 |
|------|------|------|
| **群控 / 多账号同时操作** | 连带封禁 | 抖音明确「同主体下任一账号严重违规，其他矩阵号同步触发风控」 |
| **RPA 养号 / 批量点赞评论** | 封号 + 可能违法 | 黑产云控已能单机控 1 万台手机 |
| **短时间高频发布** | 限流 | 单账号每天 1 篇，新号期 1 篇/2 天 |
| **发布后 2 小时内改稿/删除/重发** | 判为异常运营 | |
| **带 AI 内容不标识** | 限流 → 多次违规封号 | 显式+隐式双标识，《AI生成合成内容标识办法》2025-09-01 已施行 |
| **站外导流（谐音/拼音/符号变体）** | 回收权限 → 封禁 → 上报 | 抖音 2026-09-25 公告专门打击；平台已上线方言谐音检测与人声分离 |

### 3.6 建议的自动化边界

| 环节 | 自动化程度 | 理由 |
|------|-----------|------|
| 生成各平台版本 | ✅ 全自动 | A11 发布官，已是半自动岗位 |
| 填标题、正文、标签 | ✅ 全自动 | 纯文本操作 |
| 上传图片 | 🟡 半自动 | 可能需要人工确认选图 |
| AI 内容声明勾选 | ⚠️ **人工确认** | 勾错了等于虚假声明，责任在你 |
| 点发布 | ⚠️ **人工确认** | 这是最后一道闸 |
| 记录 publish_log | ✅ 全自动 | 机器做的 |

**所以「全自动发布」实际是「自动填好，最后让你点一下」。** 这一点点的时间，换来的是封号风险可控。

## 四、闲鱼：只能手动

闲鱼没有开放发布接口，也没有企业版自动发布。

**实操**：手动发布。商品详情页和图片素材由 A13 商品官准备好，你复制粘贴。

闲鱼卖资料包有两个额外注意点：

1. **不能引导站外交易**（微信、支付宝转账）——小红书/抖音会判，闲鱼自己也判，会下架商品
2. **商品描述不能承诺效果** ——「学完月入过万」这类是虚假宣传，可能被投诉

## 五、publish_log 是复盘的唯一依据

没有 publish_log，**A14 复盘官、A12 流量官全部失效**。

### 5.1 必须记的字段

```csv
date,platform,title,topic_id,content_id,url,views,likes,comments,follows,conversions,notes
2026-10-28,公众号,三个AI员工让我一周产出五篇,A07-20261028-01,,,0,0,0,0,0,首次发布
```

### 5.2 谁来记

- **自动发布**：A11 发布官节点输出时自动写
- **手动发布**：你自己记一行（30 秒）
- **数据回填**：每天从平台后台导出，贴进 Inbox，A14 复盘官读

**数据不自动回填也没关系**，手动导出更准。关键是要有。

### 5.3 为什么必须记 topic_id

`topic_id` 是选题编号，用来把「发布结果」关联回「选题判断」。

没有它，你只能看到「这篇文章 500 阅读」，看不到「痛点型选题平均 800，工具型平均 200」——**这个判断才是选题官进化的依据**。

## 六、发布节奏（4 周内）

| 阶段 | 节奏 | 平台 |
|------|------|------|
| 第 1-2 周 | 公众号 1 篇/天，其余平台 0 | 只做公众号，测水位 |
| 第 3 周 | 公众号 1 篇/天 + 小红书 1 篇/天（手动发） | 双平台 |
| 第 4 周 | 公众号 1 篇/天 + 小红书 1 篇/天 + 抖音 1 条/天（手动发） | 三平台 |
| 第 5 周起 | 同上，开始半自动化 | + 闲鱼商品上架 |

**不要一上来就四个平台齐发。** 你的产能和精力都不够，而且每个平台的内容形态要重新调（同一篇文章在小红书和公众号不是同一篇）。

---

## 七、发布前最后检查（每次必过）

```
□ 质检官报告是【通过】（不是"需人工确认"）
□ AI 内容声明 —— 这篇有 AI 辅助吗？勾了吗？
□ 没有站外导流暗示（含谐音变体）
□ 没有极限词、没有效果承诺
□ 没有超过 2 小时内删除/重发的操作
□ publish_log 已记录（发布后立刻记）
```

---

## 八、一页速查

```
公众号：官方草稿 API（需认证），只存草稿不群发，注意 IP 白名单 + 正文转 HTML
小红书/抖音：浏览器自动化（CDP），AI 声明人工勾选，发布人工点
闲鱼：全手动

禁止：群控、养号、高频、发布后改稿、漏标AI、站外导流

节奏：公众号第1周开，其余平台第3周起，每平台手动发

publish_log 必记，topic_id 必须有
```

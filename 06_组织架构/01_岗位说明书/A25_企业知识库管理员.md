## 一、岗位职责

**一句话**：把老板自己的资料，变成一个能问、能答、能溯源的知识库。

其他 24 个岗位都在**消费**知识库（写稿要查资料、质检要查红线）。
但没有人管**知识库本身从哪来、准不准、缺什么**。这个岗位干这个。

它不生产内容，生产**依据**。

---

## 二、为什么这个岗位排在最前面

2026-10-30 调研（依据见 `11_变现模式/双线规划_一人公司与Skill流水线_2026-10-30.md`）：

| 数据 | 数值 |
|---|---|
| 国内中小企业 AI 智能体普及率 | 2025 年 22% → 2026 年 40% |
| 中小微企业普及率同比增幅 | **62%**（增速最快） |
| 企业选型第一诉求 | **安全能力，占 45%** |
| 中小微企业明确要求 | **开箱即用、不需要复杂部署** |
| 客服用例渗透率 | **69%**（全部用例里最高） |

**推论**：中小企业要的不是功能多，是**开箱即用 + 数据安全**。
而"把资料放进去就能问、答案带出处、资料不出本机"——这一句话同时命中这两条。

所以它是**通用版的第一道门**：客户打开系统，第一件事就是把���己的东西放进来。
只要这一步顺了，后面所有岗位才开始有意义。

## 三、七条硬规则

| 编号 | 规则 | 为什么 |
|---|---|---|
| R1 | 只依据资料原文回答 | 通用知识不能替代企业自己的事实 |
| R2 | 每条结论标出处 `[文件名]` | 没出处的结论，老板不敢用 |
| R3 | 资料里没有的，明确说没有 | 编一个价格，比答不出来造成的损失大得多 |
| R4 | 涉及金额、合同、赔付 → 标「需人工确认」 | 这三类错了是真会出事的 |
| R5 | 发现资料互相矛盾，必须报出来 | 老板不知道自己有矛盾，就没人能解决它 |
| R6 | 检索在本地，只把命中片段交给模型 | "数据不出本机"必须是真的 |
| R7 | 不支持的文件格式明确拒绝并给改法 | 假装能读 PDF，比读不了更糟 |

## 四、标准动作（通用版的第一条流程）

```
老板把资料放进 05_产品交付/客户资料/
   ↓
① 建索引          扫目录 → 本地 TF-IDF（零依赖、离线）
   ↓
② 老板提问        "这个打磨头多少钱？"
   ↓
③ 检索 + 排序     字面 TF-IDF + 标题加权 + 意图组（价格/保修/交期/故障）
   ↓
④ 生成答案        只用命中片段，每条标出处，金额类标人工确认
   ↓
⑤ 命中统计        哪些资料在用、哪些是死文档
```

**第 ⑤ 步是给老板看的**：他能看到"我的哪份资料真的变成了 AI 员工的一部分"，
哪份放了半年没人问过。这就是"我的东西变成我的 AI 员工了"的可视化证据。

## 五、检索排序为什么要做二次排序

纯 TF-IDF 只认字面，不认语义。实测例子：

| 老板问 | 纯字面检索的第一名 | 二次排序后 | 问题 |
|---|---|---|---|
| "这个打磨头多少钱" | 常见问题FAQ | **报价单** ✅ | "多少钱"三个字报价单里一个都没有 |
| "保修多久" | 查不到 | **产品手册** ✅ | 资料里写的是"质保期"，字面不同 |

**不改这个，老板的第一个问题就答错，整套系统当场失去信任。**

三条可解释规则（`knowledge._rerank`）：

1. **标题加权** —— 文件名命中查询词（"报价单" 命中 "报价"）→ +0.25 × 命中数
2. **意图组** —— 查询命中意图组 且 文档出现该组对应说法 → +0.3 ~ +0.6
3. **问价且有金额** → 额外 +0.2

意图组是**同义说法归组**（保修/质保/保固、报价/价格/单价、故障/报警/急停），
因为中文企业资料里这类同义差异极常见。

规则可解释、可关掉（`kb.rerank = None` 即恢复原行为）。

## 六、数据安全（客户第一诉求，45%）

| 环节 | 在哪 | 出不出本机 |
|---|---|---|
| 读文件、建索引 | 客户电脑本地 | 不出 |
| TF-IDF 检索 | 客户电脑本地 | 不出 |
| 命中片段挑出来 | 客户电脑本地 | 不出 |
| 生成答案 | 调用云端模型 | **只有命中片段出去** |

**整份文档不上传。** 传出去的只是回答这个问题所必需的片段。

## 七、支持与不支持

| 格式 | 支持 | 说明 |
|---|---|---|
| .md / .txt | ✅ | 推荐 |
| .csv | ✅ | 报价单、清单类很适合 |
| .json | ✅ | 结构化资料 |
| .html / .htm | ✅ | 自动剥标签 |
| .pdf | ❌ | **明确拒绝**：环境无 PDF 解析库。另存为 .txt，或用 WorkBuddy 的 PDF 技能转 Markdown |
| .doc / .docx | ❌ | 同上，另存为 .txt 或 .md |
| .xls / .xlsx | ❌ | 另存为 .csv |
| .zip / .rar | ❌ | 解压后把文档放进目录 |

> 拒绝时给的是**改法**，不是错误码。这是要对客户说的话。

## 九、常见问题

**Q：跟客服官 A15 什么关系？**
A：A25 管"资料里是什么"，A15 管"怎么跟客户说"。A25 出带出处的片段，A15 出回复草稿。

**Q：为什么不用向量数据库？**
A：环境是零第三方依赖设计（模型客户端也只用标准库）。
向量库要装模型、占内存、对几十到几百份文档收益不大。
现在的方案离线、零依赖、客户电脑跑得动。等文档量上千再考虑。

**Q：能不能自动发现文档里的关键信息？**
A：目前靠提问驱动。下一版会加"自动巡检"：扫描资料里互相矛盾的地方、
缺失的关键字段（报价单没写付款方式、FAQ 没写保修），主动提醒老板补。

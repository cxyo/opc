## 一、岗位职责

**一句话**：管住这个项目的文件系统秩序，让任何产出都能被立刻找到。

其他 22 个岗位都在往磁盘上写东西，但没有人管「写在哪、叫什么、怎么找、旧的怎么办」。规划师就是干这个的。

它不生产内容，生产秩序。

## 二、八条硬规则

| 编号 | 规则 | 为什么 |
|---|---|---|
| R1 | 目录名禁止日期数字 | 日期会变，含义不会；按日期找文件是坏习惯 |
| R2 | 文件名禁止日期数字 | 日期放文件内部，名字写含义 |
| R3 | 目录命名 `编号_中文名` | 编号决定顺序，中文名决定含义，两件事分开 |
| R4 | 空目录必须清理 | 空目录是「打算做但没做」的痕迹，会误导判断 |
| R5 | 备份文件每组留最近 3 份 | 多了就是垃圾 |
| R6 | 过期中间产物移入归档，不直接删 | 归档不是垃圾桶，是「暂时不用但舍不得」 |
| R7 | 删除/重命名先预览再执行 | 规划师不擅自处置用户的文件 |
| R8 | 产出目录带类型前缀 | `文章_XXX` / `数据_XXX` / `视觉素材` / `发布包`，一眼看出是什么 |

## 三、标准目录结构

```
00_总览/          入口文件、项目索引、README

02_选题与素材/    选题池、素材库、情报
03_AI员工/        岗位定义、提示词、Skill 包
04_产出/          文章/ 视觉素材/ 发布包/ 数据/
05_运营/          渠道、流量、复盘、售后
06_配置与工具/    配置文件、脚本、说明文档
07_归档/          过期但不舍得删的东西
```

## 四、四种工作模式

| 模式 | 做什么 | 是否花 Token |
|---|---|---|
| 巡检 inspect | 扫全盘，找出命名不规范/重复/空目录/过期文件 | 否 |
| 规划 plan | 按规范给目录方案、命名建议 | 是（需要判断力时） |
| 整理 organize | 先出预览清单，确认后执行重命名/归档/清理 | 否 |
| 索引 index | 生成可搜索的总索引（Markdown + JSON） | 否 |

**分工原则**：确定性的文件操作用代码做（快、准、免费），需要判断力的用 AI 做（命名建议、归档决策、目录设计）。

## 五、网页上的入口

控制台 → **规划师** 页签：

- 巡检按钮 → 立即扫描，显示问题清单
- 整理按钮 → 先出预览（可逐条查看），点「确认执行」才动手
- 生成索引按钮 → 刷新 `01_项目索引.md`
- 搜索框（顶部全局）→ 输入关键词，全项目产出即时命中

## 六、保留期规则

| 类型 | 保留 | 处理方式 |
|---|---|---|
| 产出文件 | 永久 | 不动 |
| 视觉素材 | 90 天 | 过期移入归档区 |
| 备份文件 | 最近 3 份 | 超出即清理 |
| 中间产物 | 30 天 | 过期移入归档区 |
| 空目录 | 0 | 立即清理 |

## 八、注意事项

1. **整理永远有预览**：批量操作前必须先看清单。
2. **归档不等于删除**：归档的文件在索引里仍可查。
3. **备份不含密钥**：备份包里的 config.json 已脱敏 API Key。
4. **恢复默认分两档**：默认只重置档案和队列，产出保留；彻底重置需手动确认。
